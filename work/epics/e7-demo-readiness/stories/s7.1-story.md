# Story: PWA configuration — installable, offline-tolerant, correctly identified

**Branch:** `story/s7.1/pwa-configuration`
**Owner:** Rodrigo
**Backlog:** B-14 (NFR-04)

## User Story
As a demo evaluator on a phone,
I want to install the app to my home screen and have it survive a dropped connection,
so that the product demos as a real installable application rather than a browser tab.

## Acceptance Criteria

### Scenario: The app is installable on Android
```gherkin
Given the app is served over HTTPS (or localhost)
When the browser evaluates the installability criteria
Then a web app manifest is linked with name, short_name, start_url, standalone display,
  background_color, theme_color, and 192px + 512px icons
And at least one icon declares purpose "maskable" so the Android adaptive icon is not letterboxed
And a service worker is registered with a fetch handler
```

### Scenario: The app is installable on iOS
```gherkin
Given the app is opened in iOS Safari
When the user chooses "Add to Home Screen"
Then an apple-touch-icon is present so the home-screen icon is not a page screenshot
And apple-mobile-web-app-capable and status-bar-style are declared
And the launched app opens standalone, without Safari browser chrome
```

### Scenario: A navigation during a dropped connection shows the offline page
```gherkin
Given the service worker is installed and has precached the app shell
When the network is unavailable and the user navigates to any route
Then the offline fallback page is served from the cache
And it is shown in the user's active locale rather than a browser error page
```

### Scenario: A stale cache is discarded on activation
```gherkin
Given a previous service worker version cached assets under an older cache name
When a new service worker version activates
Then every cache whose name is not the current version is deleted
And the new worker claims all open clients immediately
```

### Scenario: The app identifies itself as a collections product
```gherkin
Given the E1 scaffolding left placeholder copy describing industrial wastewater treatment
When any user-facing identity string is read — manifest, document metadata, or home page
Then it describes intelligent accounts receivable and collections management
And the home page copy is resolved from the ES/EN message catalogs, not hardcoded
```

### Scenario: theme-color is declared where Next.js 15 expects it
```gherkin
Given Next.js 15 has moved themeColor out of the metadata export
When the app is built
Then themeColor is exported from a viewport object, not from metadata
And no "Unsupported metadata themeColor" build warning is emitted
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `public/manifest.json` | read `description` | a collections description; the string "wastewater" appears nowhere in the repo's user-facing copy |
| `public/manifest.json` | read `icons[].purpose` | at least one entry contains `maskable` |
| `public/manifest.json` | read `id`, `scope`, `lang`, `orientation` | `/`, `/`, `es`, `portrait` |
| `sw.js`, cache `demoiw-v1` exists, new version is `demoiw-v2` | activate event | `demoiw-v1` deleted, `demoiw-v2` retained |
| navigation request, network throws | fetch handler | cached `/offline` response returned, status 200 |
| static asset `/icons/icon-192.png`, cache hit | fetch handler | cached response returned immediately, cache refreshed in background |
| `src/app/[locale]/layout.tsx` | read `viewport.themeColor` | `#4CAF50` (hex), and `metadata.themeColor` is undefined |
| `messages/es.json` → `app.homeTitle` | compare to `messages/en.json` | both keys present, neither empty, values differ by language |

## Notes

- **next-pwa is not used.** B-14's wording ("next-pwa config") predates the Next 15 upgrade;
  next-pwa is unmaintained and webpack-only, and does not support the App Router cleanly. The
  hand-rolled service worker already present from E1 is hardened instead, adding no dependency.
  Recorded in `dev/decisions/adr-010-hand-rolled-service-worker.md`.
- The `middleware.ts` matcher already excludes `/manifest.json`, `/sw.js` and `/icons/`, so the
  service worker and its assets are not locale-rewritten. The new `/offline` route is a locale
  route and is reached through normal i18n routing.
- Installability is verified by asserting the manifest and service worker contract in Vitest.
  Real-device installation on Android and iOS hardware is out of scope for an XS story and is
  covered by the E7 demo dry-run.
- Depends on the s4.1 / B-15 i18n foundation for the offline page and home page copy.
