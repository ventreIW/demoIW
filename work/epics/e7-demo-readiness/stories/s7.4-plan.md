## Execution order

```
T1 ──→ T2 ──┬──→ T3 ──┐
            └──→ T4 ──┴──→ T5
```

Acyclic: T1 has no dependencies; T3 and T4 both depend only on T2 and are mutually independent
(they could run in parallel); T5 depends on all. No task depends on a later one.

**Risk-first rationale.** T4 is the riskiest task and would normally come first, but it
*cannot* — it reuses T2's path helper, and writing the Postgres harness against a helper that
does not exist yet would mean writing it twice. T2 is therefore the earliest point at which T4
is possible, and T4 runs immediately after. T1 precedes everything because building on contracts
already proven wrong is how the errors would propagate.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| **PostgreSQL unavailable — M4 defers a sixth time** | **High** — not installed as of this writing | T4 skips *loudly* with a reason naming M4. The gap is reported as an open gate at story close, never as a pass. |
| Migration `0004` fails on real Postgres | Medium — its `ROW_NUMBER() OVER (PARTITION BY …)` backfill has never executed | T4 tests it explicitly, including downgrade. A failure here is a genuine find and gets its own bugfix pipeline (AC9). |
| The smoke test finds new defects | Medium — five were found today on this path | Each becomes its own bugfix pipeline. s7.4 does not patch production code (AC9). |
| The test passes vacuously | Low, but catastrophic | Non-emptiness asserted before every iteration (AC3); T5 deliberately breaks a step to prove the test can fail (AC2). |
| Alembic migrations assume Postgres and cannot run on SQLite | High | Precisely why T4 is Postgres-only and the SQLite path keeps `create_all`. Not a defect. |
