# Retrospective: S7.1 — PWA configuration

**Dates:** 2026-08-18
**Estimated:** ~2 h (5 tasks) | **Actual:** ~1 h 25 min

## Summary

s7.1 turned a PWA that existed in name into one that works. The E1 scaffolding had shipped a
manifest and a `sw.js` whose `fetch` listener returned without calling `respondWith` — it cached
nothing — and the existing tests asserted on the worker's *source text*, so they passed against
that empty handler. The worker now precaches under a versioned cache, cleans stale caches on
activate, serves navigations network-first with a locale-aware offline fallback, and leaves
`/api/*` alone. `themeColor` moved to the `viewport` export Next 15 requires, document metadata
became bilingual, and iOS installability declarations landed.

The story also swept out the scaffolding's placeholder identity — "Industrial wastewater treatment
decision support" — which was still the app's description in the manifest, the document head, and
the home page of an accounts-receivable product.

Backend 545/545, frontend 206/206 (up from 167). One pre-existing blocker escalated: `npm run
build` does not succeed on `main`.

## What went well

- **Reading the code before designing paid for itself twice.** The gemba walk found both that the
  worker was a no-op and that the placeholder copy was still live. Neither was in the story brief;
  B-14 said "next-pwa config, manifest, service worker" and nothing about either.
- **Refusing the dependency was the right call.** The whole caching policy is ~60 lines of plain
  worker JS with no build step. `next-pwa` would have added a webpack integration incompatible
  with Next 15 to produce less. ADR-010 records it so the next person doesn't re-litigate.
- **The vm harness turned an untestable file into a tested one.** 17 behavioral tests that execute
  the worker, replacing 5 that grepped it.
- **Verifying against a running server caught what unit tests could not confirm** — that every
  precached URL actually returns 200. `cache.addAll` is atomic, so one 404 would have silently
  disabled the entire precache with every test still green.

## What to improve

- **The plan's per-task lint gate was never runnable and I should have said so louder up front.**
  I documented the gate deviation in the plan, then discovered at T5 that the deeper problem is
  that `npm run build` itself fails. Had T5 run first as a smoke check, the blocker would have
  surfaced 80 minutes earlier.
- **The AC named a meta tag by its deprecated name.** I wrote `apple-mobile-web-app-capable` into
  the acceptance criteria; Next 15 emits the standardized `mobile-web-app-capable`. The intent was
  met but the AC was wrong as written. Naming a *capability* rather than a *tag string* would have
  been more durable.
- **T3 and T4 had a hidden coupling.** T3's metadata tests asserted on `app.description`, whose
  correction was planned for T4. I moved the two-line fix into T3 rather than commit a red suite,
  which was right, but the plan should have placed the catalog fix in T3 from the start.

## Heutagogical Checkpoint

1. **What did I learn?** That a passing test suite says nothing about whether the thing under test
   does anything, when the test only inspects the artifact's shape. `expect(swContent).toContain("addEventListener('fetch'")`
   passed for months against a handler whose body was `return`. This is the same finding as s6.3's
   "a stub returns what you hand it", arriving from a different direction: s6.3 was a stub standing
   in for a real system, this was a test standing off from a real system. Both make the suite green
   while the behavior is absent.

2. **What would I change about the process?** Run the project's build command once at the *start*
   of any frontend story, not at the integration-test task. Five stories closed with "green gates"
   on top of a build that does not compile, because no phase of the story lifecycle runs
   `npm run build` — the test gate runs vitest, the lint gate short-circuits. A cheap smoke check
   at story start would have caught it at s6.2.

3. **Framework improvements?** Three, in descending value:
   - `rai gate check` exiting **0** when it cannot find the manifest remains the highest-value
     upstream fix visible from this project. A gate that never ran is indistinguishable from one
     that passed. Now on its fourth epic.
   - `scripts/test.sh` accepts a scope argument but routes it to pytest unconditionally, so there
     is no gate path for a scoped *frontend* test run. Every frontend story silently deviates from
     the documented gate policy. A two-line fix in `test.sh`.
   - `rai-story-implement`'s pitfall list carries a "Git Identity Confirmation (Mandatory)" block
     asserting that commits must be authored by `bernardo-525` and instructing a **stop** if the
     identity is `ventreIW` — captured from a teammate's session and now wrong for anyone else in
     the team. Session-specific facts are leaking into shared skill files as mandates.

4. **More capable of now?** Executing a browser-context file (service worker, web worker) inside
   `node:vm` with a stubbed platform API, so worker logic becomes ordinary unit-testable code
   without a headless browser. And reading a manifest against real installability criteria rather
   than against the fields that happen to be there.

## Improvements applied

- Added an **identical-value guard** to the message-parity test. s7.3's parity check compared key
  sets, which held, while `app.description` carried the same English placeholder in both catalogs.
  The guard has a reviewed 15-entry allowlist for genuine ES/EN cognates and symbols, so a new
  untranslated string fails the suite instead of shipping.
- Added an on-disk existence assertion for every manifest icon `src` — a manifest pointing at a
  missing icon is a silent installability failure.
- ADR-010 written so B-14's stale "next-pwa" wording does not get re-implemented later.

## Patterns added / reinforced

Pattern store not writable in this project (`rai graph query` / `rai pattern` still fail with
`OperationalError: no such column: data_json` — fourth consecutive epic). Recorded here instead:

- **technical** — Test a service worker by executing it in `node:vm` with a stubbed Cache Storage
  API, never by asserting on its source text. A shape assertion cannot see an empty handler.
- **technical** — ES/EN key parity is not translation coverage. Guard against *identical values*
  across locales with an explicit allowlist; identical key sets hide untranslated copy.
- **process** — Run the project's build command at story start, not at the integration task. Test
  and lint gates do not imply a compiling build.
- **process** — Precache lists must be verified to return 200 before shipping: `cache.addAll` is
  atomic, so a single 404 silently disables the whole precache with no test failure.
- Reinforced from s6.3: a green suite proves the harness agrees with itself, not that the system
  works. Spend one real invocation on any path whose output you have not actually looked at.
