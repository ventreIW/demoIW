**Complexity:** Moderate (1 new test module + 1 Postgres harness; 0 new production components)
**Integration gate:** TRIGGERED — story name contains "E2E". AC therefore includes a scenario

## PRIME

`rai graph query` returned nothing — still failing with `no such column: data_json`, now the

## Problem

E7's brief promises "validated end-to-end so the full <10-minute demo flow is proven to work
without assistance". Nothing proves it. Five defects sitting directly on the demo path were
found and fixed today (BUG-01…BUG-05), all of which this test would have caught, and one of
which — non-deterministic scoring — had survived four epics.

## Value

The demo can be rehearsed with confidence, and a broken step is discovered by a test rather
than in front of an audience. Secondarily, it closes E6's M4, open across five stories.

**Duplicate check — the important finding.** `tests/test_e2e_intelligence_path.py` already
exists and already does in-process E2E for the *intelligence* path
(generate → score+persist → prioritized → rescore). It must be extended in coverage, not
duplicated. Its own docstring states the Postgres run "remains an environment-dependent step
documented at epic close" — which is precisely how M4 survived five stories.

**`conftest.py` builds the schema with `Base.metadata.create_all` against SQLite in-memory.**
The Alembic migrations are therefore never executed by any test. This is the concrete reason
M4 matters, and it now matters more: migration `0004` (BUG-05) is new and unexercised.

## Legacy sweep

**(c) V1 coexists, deliberately.** `test_e2e_intelligence_path.py` is a narrow, fast check of
the E4 seams and runs in ~1s. The new `test_e2e_demo_flow.py` is the *whole product path*
(E4+E5+E6) and is slower. Keeping both means a broken scoring seam is diagnosed by the narrow
test rather than by a 10-step failure. Nothing is orphaned; no production code is superseded.

## Approach

One new test module driving the full path in a single ordered run, plus a Postgres harness
that runs the same path against a real database with migrations applied from zero.

**KISS/YAGNI:** no new framework, no Playwright, no fixtures library. Plain pytest + the
existing `AsyncClient` fixture pattern. The Postgres harness is ~40 lines and gated on an
environment variable.

**Non-vacuity is a design constraint, not a review item.** Every collection assertion asserts
non-emptiness *before* iterating. BUG-02 was concealed for four epics by a loop over an empty
list, and this story is the one place where that shape would be most damaging — a smoke test
that passes because nothing happened is worse than no smoke test.

**Skip loudly.** If PostgreSQL is unreachable the Postgres test calls `pytest.skip` with an
explicit reason naming M4. It must never pass silently: silent passing is the exact mechanism
by which M4 accumulated five stories of deferral.

**Data mutation strategy:** the flow only creates. No entity is referenced that the flow did
not itself create, so there is no missing-entity path to declare.

**Supply chain gate:** N/A — no new dependencies. `asyncpg`, `alembic`, `pytest`, `httpx` are
already direct dependencies.

**Drift risk:** `governance/drift-hotspots.json` absent — step skipped per graceful
degradation. AG2 (clone amplification) assessed: the legacy sweep above is the mitigation —
coverage is extended rather than copied. AG4 (fan-out) not applicable: one new test module,
one test-config change, no production modules touched.

## Decisions

**D1 — One ordered test, not ten independent ones.** The demo is a *path*; step 7 is only
meaningful given steps 1–6. Independent tests would each re-generate a scenario, would not
prove the path composes, and would not give a wall-clock number for NFR-01.

**D2 — Assert the wall clock, but generously.** NFR-01 is "under 10 minutes" for a *human*
demo. The automated path will run in seconds. Asserting the real NFR-01 budget makes the test
meaningful against the requirement without being flaky; the measured elapsed time is reported
so drift is visible.

**D3 — The LLM is stubbed for the path, not mocked away.** Following
`test_e2e_intelligence_path.py`'s `_NoLLM` pattern: the comms and NL-query steps must exercise
their real degradation contract (`ExternalServiceError` → handled response), which is what
s6.0 hardened. A live-model run is a separate manual check, not a CI gate — free-tier limits
are 50 requests/day per key.

**D4 — Postgres runs the same test body, not a copy.** The path is written once as a helper
and invoked by both the SQLite test and the Postgres test. A copied body would drift.

**D5 — CSV upload is exercised to its real limit.** BUG-06 means an uploaded scenario cannot
be scored. The test asserts upload → persisted → listed, and asserts the BUG-06 boundary
explicitly, so the gap is visible in the demo-readiness signal rather than hidden by omission.

## Examples

```python
# The path, in order, with the real contracts.
GEN = {"seed": 42, "sector": "retail", "client_count": 100, "invoice_volume": 5.0,
       "amount_mean": 10000.0, "amount_std": 3000.0, "reference_date": "2026-06-01"}

r = await client.post("/api/v1/scenarios/generate", json=GEN)          # 201
sid = r.json()["id"]
await client.patch(f"/api/v1/scenarios/{sid}/activate")                 # 200  (PATCH!)
await client.post(f"/api/v1/scenarios/{sid}/score")                     # 201  scored_count > 0
q = await client.get(f"/api/v1/scenarios/{sid}/prioritized")            # 200  cases non-empty
cid = q.json()["cases"][0]["client_id"]
await client.get(f"/api/v1/scenarios/{sid}/clients/{cid}")              # 200  invoices present
await client.post(f"/api/v1/scenarios/{sid}/clients/{cid}/contact-result",
                  json={"scenario_id": sid, "client_id": cid,
                        "contact_result": "promise_to_pay"})            # 201
await client.post(f"/api/v1/scenarios/{sid}/clients/{cid}/communications",
                  json={"channel": "email", "tone": "formal"})          # 201
k = await client.get(f"/api/v1/scenarios/{sid}/kpis")                   # 200
assert k.json()["total_outstanding"] > 0                                # NOT total_overdue
await client.post(f"/api/v1/scenarios/{sid}/query",
                  json={"question": "¿Cuánto se debe por categoría?"})  # 200
```

## Acceptance Criteria

**MUST**
- AC1 — One test drives all ten steps in order; each asserts status and a well-formed payload.
- AC2 — Deliberately breaking one step makes the test fail and name that step (demonstrated).
- AC3 — No assertion can pass over an empty collection; non-emptiness is asserted first.
- AC4 — Elapsed wall-clock time is asserted under the NFR-01 budget and reported.
- AC5 — The same seed twice yields an identical score multiset and category tally (BUG-05).
- AC6 — The same path passes against real PostgreSQL with `alembic upgrade head` from zero,
  and `0004` downgrades cleanly; if Postgres is unreachable the test **skips with a reason
  naming M4**.

**SHOULD**
- AC7 — CSV upload exercised to its BUG-06 limit, with the boundary asserted explicitly.
- AC8 — The three contract errors found in gemba are corrected in `s7.4-story.md`, and the
  wrong KPI key in BUG-03's xfail test is fixed.

**MUST NOT**
- AC9 — MUST NOT modify production code. A defect found here gets its own bugfix pipeline.
- AC10 — MUST NOT duplicate `test_e2e_intelligence_path.py`; the path helper is written once
  and shared between the SQLite and Postgres runs.
- AC11 — MUST NOT pass when PostgreSQL is absent while appearing to have verified it.

## Testing strategy

| Layer | Name | Purpose |
|---|---|---|
| E2E (SQLite/ASGI) | `test_full_demo_path` | The ten steps compose and complete in budget |
| E2E (SQLite/ASGI) | `test_demo_path_is_repeatable` | BUG-05 reproducibility across two runs |
| E2E (**Postgres**) | `test_full_demo_path_on_postgres` | M4: asyncpg + migrations from zero |
| Migration | `test_migration_0004_roundtrip` | `upgrade head` then `downgrade -1` cleanly |
| Boundary | `test_csv_upload_limit_is_explicit` | BUG-06 asserted, not hidden |
