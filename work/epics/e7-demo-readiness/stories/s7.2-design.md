# S7.2: Accessibility pass (WCAG 2.1 AA) — design

## Problem
The demo UI fails WCAG 2.1 AA: primary/default buttons and focus rings reference Taiwind tokens (`bg-primary`, `ring-ring/50`, `border-ring`) that are **never defined** (empty `theme.extend`, no CSS variables in `globals.css`) → primary buttons render with no background and focus indicators are invisible. `text-slate-400/500` accents and status chips fall below the 4.5:1 contrast ratio; tables lack header semantics; sidebar and several custom buttons have no focus style; there is no skip-link or landmark labeling.

## Value
Make every demo page usable by keyboard-only users and legible at WCAG 2.1 AA, so the Aug-14 demo can be shown safely to anyone. A passing automated a11y scan (0 AA violations) is an observable, verifiable signal.

## Approach
WCAG audit + targeted CSS/JSX fixes. No new runtime dependency. Introduce a small set of design tokens in `globals.css` (`--background`, `--foreground`, `--primary`, `--muted`, `--ring`, etc.) so the existing shadcn-style primitives (button/input/select) regain their intended styles and visible focus rings; add a global `focus-visible` fallback; bump low-contrast slate shades to pass 4.5:1; add `th scope`, a skip-to-content link, landmark roles, and `aria-current` to the sidebar; ensure the audit is repeatable via a script (axe-core, devDep only).

Changes are in-place — no new abstractions, no component-library adoption (YAGNI for the demo deadline). This is the smallest change set that yields 0 AA violations.

## Decisions
- **D1 — Add tokens instead of per-file color swaps:** the root cause is undefined tokens. Defining the four/five reused tokens once restores the whole primitive set and guarantees consistent contrast. Rationale: fixes ~15 components via one change set rather than 15 ad-hoc swaps.
- **D2 — Keep Base UI primitives, don't adopt a design system:** existing buttons/select/input already carry `focus-visible:ring-*`; fixing tokens is minimal and leverages what exists. No new dependency (KISS/YAGNI for the deadline).
- **D3 — axe-core as devDependency for the repeatable scan:** well-established package, dev-only, simplest verifiable "0 violations" gate. Ranked vs a hand-rolled contrast matrix (too brittle).
- **D4 — No skip-gate on contrast of *decorative* icons:** `[aria-hidden]` icons are exempt; only text/UI components must pass.

## Complexity
Simple→Moderate. Many files touched but all mechanical, one root cause (tokens), zero backend, zero new runtime deps.

## Dependencies
- No runtime deps. DevDep: `axe-core` (audit + unit-level checks).
- Builds on base-ui primitives and E6 hand-rolled CSS.

## Legacy sweep
**"nothing — this is net-new."** No V1 pattern is replaced; the token definitions and focus fallback are additive, and existing shadcn-style class names are preserved so nothing orphanes.

## Drift risks
- AG2 (clone amplification): avoid copy-pasting focus classes across every component — rely on the shared token/focus fallback. Mitigation: keep fixes in shared `globals.css`/primitives where possible.
- No drift-hotspots.json present in this branch (skipped silently).

```css
*:focus-visible { outline: 2px solid var(--ring); outline-offset: 2px; }
```

## Acceptance Criteria
MUST:
- **AC1** axe-core scan reports 0 WCAG 2.1 AA violations on cases, executive, NL-query, and scenarios (upload) pages.
- **AC2** Primary/default buttons now have a visible background and pass AA contrast (token fix verified).
- **AC3** Every interactive element (sidebar links, custom upload/cancel buttons, locale switcher, inputs, selects) shows a visible, non-clipped focus indicator on keyboard focus.
- **AC4** `th scope` present on data tables; inputs have programmatically-associated labels/aria-label.
- **AC5** Skip-to-content link added to `MainLayout`; `<nav>` landmark and `aria-current` on active sidebar; `main` has a label.
- **AC6** `vitest` green (with `--no-coverage` per WSL), no TypeScript errors; ES/EN i18n key parity holds.

SHOULD:
- Repeated Tab order is logical (follows visual layout) across all panels.
- Focus returns to the invoking control on dialog/modal close.

MUST NOT:
- Do not introduce a design-system/component library for this pass.
- Do not degrade existing layout/styling; no font-size or color regressions on non-affected elements.
- Do not silently drop any existing `aria-label` or `aria-hidden` intent.
