# S7.1: PWA configuration plan

**Story:** s7.1 | **Size:** XS–S | **Date:** 2026-08-18 | **Branch:** `story/s7.1/pwa-configuration`

Four implementation tasks plus a mandatory manual integration test. Decomposition is by file
concern — each task owns one contract and one commit.

## Gate Policy

| When | Command | Scope |
|------|---------|-------|
| Per task | `bash scripts/typecheck.sh` | Full project (frontend tsc + backend mypy) |
| Per task | frontend tests, scoped — see deviation below | Only the test files for the changed module |
| End of story | `cd frontend && npm test -- --run` | Frontend suite only — backend is untouched by this story |
| Merge | `bash scripts/test.sh` | Full suite — the only place unscoped tests run |

**Deviation from the standard gate policy, stated explicitly.** `rai gate check` is not usable
here for two reasons already recorded in the E6 retrospective and confirmed at plan time:

1. `rai gate check` exits **0** when it cannot find `.raise/manifest.yaml`, so a gate that never
   ran is indistinguishable from a gate that passed. It must be run from the repo root, and even
   then it delegates to the scripts below.
2. `scripts/test.sh` accepts a scope argument but routes it to **pytest only** — there is no path
   through the gate script that runs a scoped *frontend* test. Since s7.1 is frontend-only, every
   per-task test run in this plan invokes `npx vitest run <path>` directly from `frontend/`.

`scripts/lint.sh` and `scripts/format-check.sh` are additionally known to short-circuit under
`set -e` with the frontend first; ESLint is also known to time out on this WSL host. Lint is
therefore run per-task as `npx eslint <changed files>` rather than through the script, and the
result recorded honestly in the progress log — including if it times out.

## Execution order

```
T1 ─┬─> T3 ─┐
    │       ├─> T5
T2 ─┴─> T4 ─┘
```

T1 and T2 are independent and carry the story's only real unknowns (manifest contract, vm test
harness), so they go first — risk-first. T3 depends on T1 only for the icon path. T4 is last of the
implementation tasks because it is the lowest-risk and largest-surface change. T5 gates the story.
The graph is acyclic.

## Risks

| Risk | Mitigation |
|---|---|
| `getTranslations` may need a request context under vitest | T3 has an explicit fallback (mock `next-intl/server`); resolved by running, not by guessing |
| `node:vm` harness may not model the Cache Storage API faithfully enough to be meaningful | T5's real-browser offline check is the backstop — the harness proves logic, the browser proves integration |
| `cache.addAll` fails atomically; a 404 on any precache URL silently disables the whole precache | Precache list is restricted to assets certain to exist (D4); T5 verifies the cache contents in DevTools |
| ESLint times out on this WSL host (pre-existing) | Run `npx eslint` on changed files only; if it still times out, record it as skipped rather than claiming it passed |
| A stale `demoiw-v1` cache on a developer machine can mask changes | Worker calls `skipWaiting` + `clients.claim`; T5 instructs a hard reload |
