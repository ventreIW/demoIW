# Story: English translation pass — complete EN copy for all modules

## User Story
As an English-speaking demo evaluator,
I want every user-facing screen to read as polished, idiomatic English,
so that the product demos natively well in English without awkward or inconsistent copy.

## Acceptance Criteria

### Scenario: Every UI string is present and idiomatic in English
```gherkin
Given the full set of UI copy across all modules (sidebar, scenarios, CSV upload, operations,
case detail, contact result, communications, executive panel)
When I review the English translation file for each of those sections
Then every key has a correct, idiomatic English value and no key is untranslated, omitted, or left as Spanish
```

### Scenario: EN/ES key parity and no stale value
```gherkin
Given both locale files (en.json, es.json)
When I compare their key sets and values
Then the key sets match exactly and no English value accidentally equals a Spanish-only string
```

### Scenario: English is the demonstrated default for a locale switch
```gherkin
Given a user switches the UI language to English
When they navigate through the demo screens
Then no screen shows a hardcoded Spanish string, and the language switcher reflects the active locale
```

### Scenario: All modules use the translation layer
```gherkin
Given the frontend source
When I search for user-facing text
Then no user-facing string is hardcoded outside the i18n key system
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| `executivePage.query.placeholder` | Switch to EN | "Type a question in Spanish…" is a legitimate instructional EN string, not a leftover ES placeholder |
| `csv.successCreated` | Switch to EN | "Scenario \"{name}\" created successfully." |
| `communications.sendConfirm` | Switch to EN | "Are you sure you want to send this communication?" |
| Any section | Compare en.json vs es.json | identical key sets; 0 missing in en |
| Any component | grep for `useTranslations` | all user-facing components use i18n hooks (no hardcoded JSX text) |

## Notes
- E7 Demo Readiness (brief.md). S-sized English (EN) copy completion pass building on the s4.1/B-15 i18n foundation.
- Current state (verified 2026-08-14): `frontend/messages/en.json` already has 172 keys with full key parity to `es.json`; all user-facing components already call `useTranslations(...)`. Work here is **review, polish, and fix inconsistencies** rather than greenfield translation.
- Known items to verify: ~16 key values currently identical across en.json/es.json (e.g. `app.description`, `scenarioForm.sector`, `caseDetail.sectionScore` "Score"); ensure each is the correct English rendering and not a Spanish value reused.
- Backend NL-query responses and generated communication drafts are intentionally out of scope (they are not UI copy).
- Verification tooling: JSON key-parity script + `vitest` for any copy-dependent test; no live Postgres E2E in this environment.
