# s7.4 — End-to-end demo flow validation · scope

**Branch:** `story/s7.4/e2e-demo-flow-validation` · **From:** `main` · **Epic:** E7 · **Size:** S

## In Scope

- An automated backend smoke test driving the full demo path in one run:
  generate → activate → score → prioritized queue → category filter → case detail →
  contact result → communication draft → executive KPIs → NL query.
- A wall-clock assertion for NFR-01 (the whole path under 10 minutes).
- A reproducibility assertion: the same seed yields the same portfolio (BUG-05).
- Non-vacuity by construction: every collection assertion checks non-emptiness first, so no
  step can pass by iterating nothing (the BUG-02 shape).
- The same path executed against **real PostgreSQL** with Alembic migrations applied from
  zero, satisfying E6's M4 — including the new `0004` migration's forward and backward paths.
- CSV upload exercised to its current limit, with the BUG-06 boundary asserted explicitly.

## Out of Scope

| Item | Reason / destination |
|---|---|
| Browser-level E2E (Playwright/Cypress) | No such harness exists in this project; introducing one is its own story. The frontend is covered by 207 Vitest tests and s7.2's axe scans. |
| Fixing BUG-06 (uploaded scenarios unscorable) | ADR-level decision on scoring unlabelled data; escalated, not absorbed here. |
| Load or performance testing beyond the NFR-01 wall clock | NFR-02 (500 clients) is E6 s6.2's deferred item, not this story. |
| The 13 pre-existing `format:check` failures | Recorded in BUG-01's retro; a separate concern. |
| Deploying to Vercel/Railway | Explicitly out of project scope — demonstrative only. |

## Done when

1. A single test drives every step above and asserts a success status and a well-formed
   payload at each one.
2. The test fails, naming the step, if any step breaks — verified by deliberately breaking one
   and observing the failure message.
3. No assertion in the test can pass over an empty collection.
4. Wall-clock elapsed time for the full path is asserted under 10 minutes and reported.
5. Running the path twice with the same seed produces an identical score multiset and category
   tally.
6. The suite passes against real PostgreSQL with migrations applied from zero, and `0004`
   downgrades cleanly. If no PostgreSQL is reachable the Postgres test **skips with an explicit
   reason** — it must never pass silently, since silent passing is what let M4 survive five
   stories.
7. Full backend suite green; `ruff` and `mypy` clean; frontend gates untouched and still green.
