# S7.2: Accessibility pass — WCAG 2.1 AA scope

## In Scope
- WCAG 2.1 AA contrast audit of all pages/panels: dashboard (s6.2), executive + NL query (s6.4), case detail (s5.2), contact/result form (s5.3), upload flow (s2.4)
- Fix color-contrast violations in hand-rolled CSS (no new design-system dependency)
- Full keyboard navigation across all panels: logical Tab order, Enter/Space activation, Shift+Tab reverse
- Visible, non-clipped focus indicator on every interactive element
- Programmatic/visible labels for all inputs, icon buttons (aria-label/title), tables, dialogs
- Focus management on dialog open/close and mobile nav (return focus to invoking control)
- Automated a11y scan (axe-core or Lighthouse) wired into verification; Vitest where UI logic is testable
- i18n keys for any new aria/label copy in ES/EN

## Out of Scope
- PWA config / service worker (s7.1)
- English translation pass (s7.3)
- Full-screen-reader remediation beyond WCAG AA (e.g. AAA contrast, complex ARIA redesigns)
- Backend changes; DB; real-Postgres E2E (standing environment blocker, E7)
- Introducing a design-system or component library

## Done when
- axe-core / Lighthouse scan reports 0 WCAG 2.1 AA violations on all demo pages
- Every interactive element is reachable and activatable using only the keyboard
- Focus indicator is visible on every focused control and not clipped
- All inputs/icon-only buttons have accessible names; dialogs manage focus correctly
- No regression: `vitest` green, no TypeScript errors, ES/EN i18n key parity holds
- Story retrospective written
