# Story Design: S7.3 — English translation pass

> **Epic**: E7 - Demo Readiness
> **Complexity**: simple | **Size**: S

---

## 1. What & Why

**Problem**: The demoIW frontend locale files (`frontend/messages/en.json`) already has 172 keys with full parity to `es.json`, but ~16 key values are identical between EN and ES. Some of these are legitimate (proper nouns, units), but others may read as awkward or Spanish-idiom carried over. The EN copy has never had a dedicated human review for natural, idiomatic English.

**Value**: English demo evaluators see polished, native English across all modules — no Spanish-idiom artifacts, awkward phrasing, or inconsistent terminology. Improves demo credibility and product perception in EN track.

---

## 2. Approach

Review and polish every value in `frontend/messages/en.json` — module by module — focusing on natural idiomatic English. This is a copy review exercise, not a code change story, though one minor code cleanup is included.

**Components affected**:
- **`frontend/messages/en.json`**: modify — review and polish 172 key values (English-only; ES kept as-is)
- **`frontend/src/components/scenarios/GenerateScenarioForm.tsx:108`**: modify — remove Spanish inline comment `{/* Número de clientes */}` (orphaned note from initial i18n pass)

**KISS**: Single-file copy review. No new components, no new hooks, no new patterns.
**DRY**: No duplication risk — this is the sole English locale file.
**YAGNI**: No speculative features — exactly what the epic scope calls for.
**MVP**: Polish EN copy across all 13 sections. Verify coverage. Run gates.

### Legacy sweep

Nothing — this is net-new copy polish, not a V2 of anything.

### Drift risk

No drift risk identified. The change is confined to a single JSON locale file. AG2 (clone amplification) and AG4 (context-window planning) are not triggered.

### Supply chain gate

No new external dependencies. N/A.

## 4. Acceptance Criteria

### Must Have

- [ ] Every key in `frontend/messages/en.json` is reviewed and polished for idiomatic English
- [ ] EN/ES key sets match exactly (script-verified: 172 keys both, 0 diff)
- [ ] Spanish comment `{/* Número de clientes */}` removed from GenerateScenarioForm.tsx
- [ ] All gate checks pass: `test.sh` (vitest) green, `typecheck.sh` (tsc --noEmit) green, `lint.sh` clean
- [ ] No user-facing string in `src/` is hardcoded outside the i18n system

### Should Have

- [ ] Verify the locale switcher renders the `en` locale correctly in routing
- [ ] Check that `executivePage.query.placeholder` ("Type a question in Spanish…") displays correctly in EN (this IS correct — it's an instructional string telling users what language the NL query understands)

### Must NOT

- [ ] Do NOT modify `frontend/messages/es.json` — ES is the baseline, not the target of this story
- [ ] Do NOT add new i18n sections/keys not already in the 172-key structure
- [ ] Do NOT refactor or restructure component code beyond removing the single Spanish comment
