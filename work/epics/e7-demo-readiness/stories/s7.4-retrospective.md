# Retrospective: s7.4 — End-to-end demo flow validation

**Date:** 2026-08-20 (single session) · **Estimated:** S (5 tasks) · **Actual:** S, as planned
**Branch:** `story/s7.4/e2e-demo-flow-validation`

## Summary

E7's last story. One test module drives all ten steps of the presenter's path — generate,
activate, score, prioritized queue, category filter, case detail, contact result,
communication draft, executive KPIs, NL query — plus repeatability, the CSV boundary, and a
PostgreSQL run for E6's M4. **555 backend tests pass; the demo path completes in 1.41s against
a 600s budget.** No production code was changed.

Delivered fully except M4, which is written and ready but skipped: PostgreSQL is not installed
on this host.

## What went well

**The gemba walk paid for itself immediately.** Reading the live OpenAPI schema rather than the
domain classes found three wrong contracts in the story artifact I had written an hour earlier
— `activate` is `PATCH` not `POST`, case detail is `/clients/{id}` not `/cases/{id}`, and the
KPI field is `total_outstanding` not `total_overdue`. Had I written the test from the story
artifact, all three would have surfaced as confusing failures. This is [[verify-enum-values-against-source]]
applying exactly as recorded.

That third error also propagated: BUG-03's strict-xfail test, written earlier the same day,
asserted `total_overdue`. It is unreached today, but it would have failed for the *wrong
reason* the moment BUG-06 was fixed — a booby trap for a future session. Fixed in T1.

**The duplicate check prevented a real duplication.** `test_e2e_intelligence_path.py` already
did in-process E2E for the E4 seams. Extending coverage rather than copying kept the fast
diagnostic test intact, and its docstring turned out to contain the whole M4 story: the
Postgres run "remains an environment-dependent step documented at epic close." That sentence
is how a mandatory gate became optional for five stories.

**Proving the test can fail was worth more than writing it.** Two deliberate breakages, each
reverting a defect fixed earlier today, both caught with precise messages. Probe 2 is the
instructive one: reverting BUG-05 produced a *plausible* distribution on every individual run.
Nothing looked wrong in isolation. Only the cross-run comparison exposed it — which is exactly
why it survived four epics, and exactly why a smoke test that only ever passes proves nothing.

## What to improve

**I nearly shipped a test that could only see failure.** The first version stubbed the LLM to
always raise, following `test_e2e_intelligence_path.py`'s pattern. That correctly exercises
s6.0's degradation contract — and it means the demo's headline moment, a question answered with
a chart and a narrative, was never once verified. A demo-readiness test that only ever watches
the LLM fail proves the product does not crash; it does not prove the demo works. Caught only
because I probed what the comms step actually returned instead of trusting the `201 or 502`
assertion I had written. **An assertion permitting two outcomes verifies neither until you know
which one occurs.**

The fix — a scripted well-formed LLM — also let me assert something better: the scripted
narrator emits chain-of-thought before the `RESPUESTA:` marker, reproducing the exact live bug
s6.3 found where a reasoning model's trace reached the director. That is now a regression guard
rather than a story in a docstring.

**My acceptance criteria were wrong twice today** — here in the story artifact, and in BUG-04
where criterion 3 asserted against the generator's design. Both were written before reading the
implementation. The pattern is clear enough to name: criteria drafted at scope time encode
assumptions, and the design phase's gemba walk is where they must be re-verified, not merely
elaborated.

## Heutagogical Checkpoint

1. **What did I learn?** That no test in this project has ever executed an Alembic migration.
   `conftest.py` builds the schema with `Base.metadata.create_all` against SQLite, so the
   Postgres-specific DDL — including `0004`, added today, whose backfill uses
   `ROW_NUMBER() OVER (PARTITION BY …)` — is entirely unexercised. M4 is not a formality; it
   is the only thing standing between this project and a migration nobody has run.

2. **What would I change about the process?** Verify what an assertion actually observes, not
   only that it passes. `assert response.status_code in (201, 502)` passed on the first run and
   told me nothing, because I had not checked which branch was taken. One probe turned a
   meaningless assertion into two meaningful tests.

3. **Framework improvements?** Three, all measured this session. (a) `rai gate check` exits 0
   while printing `FAILED: 5 of 15 gates failed` — a gate that cannot fail cannot enforce, and
   this is the single highest-value RaiSE fix visible from this project. (b) `--scope backend`
   from the repo root breaks `gate-tests` because pytest's rootdir is already `backend/`, so
   the invocation recorded as correct in project memory is itself wrong. (c) `rai pattern add`
   reports success and writes nothing — no DB, no JSONL, no file anywhere under `.raise/`.
   Three epics of pattern capture have been lost, and the silent success is why nobody noticed.

4. **More capable of now?** I can recognise a test that cannot fail — the vacuous loop
   (BUG-02), the gate nobody runs (BUG-01), the feature tested only up to persistence
   (BUG-03), and now the assertion that permits both outcomes. They are one family: **the test
   observes a proxy for the outcome rather than the outcome.**

## Patterns added / reinforced

**Added: none — `rai pattern add` is a verified no-op.** Three calls during BUG-01 reported
success and wrote nothing; not re-attempted. Preserved here instead:

- A test that permits two outcomes verifies neither until you confirm which one occurs.
- Stub-always-fails proves degradation, not function. A demo-readiness test needs both paths.
- Acceptance criteria written before reading the implementation encode assumptions; the gemba
  walk is where they get re-verified, not just elaborated.
- A skip must name what it did not verify. "Skipped" and "passed" are indistinguishable in a
  summary line, which is how M4 accumulated five stories of deferral.

**Reinforced:** [[verify-enum-values-against-source]] — **+1**, decisively. It caught three
contract errors and one latent booby trap in a single story. [[raise-framework-fidelity]] —
**+1**: the full lifecycle was run for this story and for all five bugfixes.
