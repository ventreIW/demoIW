# S7.1: PWA configuration design

**Complexity:** Simple–Moderate (6 files modified, 4 created, 0 new dependencies, 0 external integrations)

## Problem

The PWA assets in `frontend/public/` are E1 scaffolding stubs, not a working PWA. The service
worker registers a `fetch` listener that returns nothing and caches nothing, so the app is
installable in name only and dies at the first dropped packet. The manifest has no `id`, no
`scope`, and no maskable icon, so Android letterboxes the adaptive icon; nothing declares
`apple-touch-icon`, so an iOS home-screen install shows a page screenshot instead of an icon.
Separately, the scaffolding's placeholder description — "Industrial wastewater treatment decision
support" — is still the app's identity in six places, including the manifest and the home page.

## Value

The manifest and home screen are the first thing a demo evaluator sees on a phone, and right now
they announce the wrong product. Observable after this story: the install prompt fires with a
correct name and a clean adaptive icon, an offline navigation lands on a localized page instead of
the browser's dinosaur, and the string "wastewater" no longer appears anywhere in user-facing copy.

## Approach

Harden the service worker that already exists rather than introducing a PWA build plugin. Complete
the manifest, move `themeColor` to the `viewport` export that Next 15 requires, and derive the
document metadata from the locale catalogs so title and description are bilingual like the rest of
the app.

**Lean gates.** *KISS*: the whole caching policy is ~60 lines of plain worker JS with no build
step — a plugin would add a webpack integration to generate less than we hand-write here. *DRY*:
gemba found no existing cache, offline route, or apple-icon declaration to reuse; this is net-new
behavior on an existing file. *YAGNI*: cut from scope — push notifications, background sync, share
target, app shortcuts, and cached API responses. None are demoed. *MVP*: installability plus one
offline fallback page is the smallest thing that makes the PWA claim true.

**Supply chain gate:** N/A — no new dependency. See D1.

**Drift risk:** `governance/drift-hotspots.json` and `drift-catalog.md` are absent in this project,
so the ranked-hotspot check is skipped. AG4 (fan-out) assessed manually: the change touches 4
source modules with no coupling edges between them beyond the message catalogs. AG2 (clone
amplification): none — no logic is duplicated.

**Legacy sweep:** Nothing is orphaned. This is not a V2 — `public/sw.js` and `public/manifest.json`
are modified in place, and every existing consumer (the registration script in the layout, the
`middleware.ts` matcher exclusions) keeps working unchanged. The two existing PWA test files are
rewritten rather than superseded: `sw.test.ts` currently asserts on the *source text* of the worker
(`expect(swContent).toContain("self.addEventListener('install'")`), which cannot detect that the
fetch handler does nothing. It is replaced with behavioral tests that execute the worker. No file
is left behind.

## Decisions

**D1 — Harden the hand-rolled service worker; do not adopt next-pwa.**
B-14 was written before the Next 15 upgrade. `next-pwa` is unmaintained, webpack-only, and does
not support the App Router cleanly; `@serwist/next` is the maintained successor but adds a
build-time generation step and two dependencies to produce a caching policy this story can express
in ~60 lines. For a demo asset with no offline *functionality* requirement, the dependency is not
earned. Recorded as ADR-010. Revisit if offline data access ever enters scope.

**D2 — Document metadata comes from the locale catalog via `generateMetadata`.**
The layout currently exports a static `metadata` object with a hardcoded English description, and
`app.description` already exists in both catalogs but is referenced nowhere. Switching to
`generateMetadata({ params })` + `getTranslations` fixes both: the document title and description
become bilingual, and the orphan key gets a consumer. The static `viewport` export stays static —
`themeColor` does not vary by locale.

**D3 — The offline fallback is locale-aware by path prefix, not by negotiation.**
The worker cannot run `next-intl`. Since `localePrefix: 'as-needed'` means English routes are the
only prefixed ones, the worker checks whether the failed navigation's pathname starts with `/en`
and serves `/en/offline` or `/offline` accordingly. Both are precached. This is a two-locale
heuristic and is documented as such in the worker; it is not a general negotiation mechanism.

**D4 — Precache the fallback and icons, not the app shell routes.**
`/` and `/en` render live data from the backend; caching them would let a stale dashboard be
served as if fresh. `cache.addAll` also fails atomically, so every precached URL must be certain to
exist. The precache list is therefore the two offline routes, the manifest, and the icons. Live
routes are network-first and fall through to the offline page.

**D5 — Test the worker by executing it, not by reading it.**
The existing `sw.test.ts` asserts that the file *contains* `"self.addEventListener('fetch'"` — a
test that passes against the current do-nothing handler. The replacement loads the file into a
`node:vm` context with a stub Cache Storage API and invokes the captured listeners, so the assertions
are about what the worker does. This is the same lesson as s6.3's stub finding: a test that can
only see the shape of a thing cannot see that the thing is empty.

**Service worker fetch policy:**

```js
const CACHE_VERSION = 'demoiw-v1'
const PRECACHE_URLS = [
  '/offline',
  '/en/offline',
  '/manifest.json',
  '/icons/icon-192.png',
  '/icons/icon-512.png',
  '/icons/apple-touch-icon.png',
]

self.addEventListener('fetch', (event) => {
  const { request } = event
  if (request.method !== 'GET') return
  if (new URL(request.url).origin !== self.location.origin) return

  if (request.mode === 'navigate') {
    event.respondWith(networkFirst(request))
  } else if (isStaticAsset(new URL(request.url).pathname)) {
    event.respondWith(staleWhileRevalidate(request))
  }
})

async function networkFirst(request) {
  try {
    return await fetch(request)
  } catch {
    const cache = await caches.open(CACHE_VERSION)
    return (
      (await cache.match(request)) ??
      (await cache.match(offlineUrlFor(new URL(request.url).pathname)))
    )
  }
}

function offlineUrlFor(pathname) {
  // localePrefix is 'as-needed': only English routes carry a prefix.
  return pathname === '/en' || pathname.startsWith('/en/') ? '/en/offline' : '/offline'
}
```

**Layout exports:**

```ts
export const viewport: Viewport = {
  themeColor: '#4CAF50',
  width: 'device-width',
  initialScale: 1,
}

export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: string }>
}): Promise<Metadata> {
  const { locale } = await params
  const t = await getTranslations({ locale, namespace: 'app' })
  return {
    title: t('title'),
    description: t('description'),
    applicationName: t('title'),
    manifest: '/manifest.json',
    icons: { icon: '/icons/icon-192.png', apple: '/icons/apple-touch-icon.png' },
    appleWebApp: { capable: true, statusBarStyle: 'default', title: t('title') },
  }
}
```

## Acceptance Criteria

**MUST**

| ID | Criterion | Verified by |
|---|---|---|
| AC1 | Manifest declares `id`, `scope`, `start_url`, `standalone`, `lang`, hex colors, and 192+512 icons including a `maskable` entry | `manifest.test.ts` |
| AC2 | The worker precaches under `demoiw-v1` on install and deletes every non-current cache on activate, then claims clients | `sw.test.ts` |
| AC3 | A failed navigation resolves to the precached offline page, `/en/offline` for `/en/*` paths and `/offline` otherwise | `sw.test.ts` |
| AC4 | Static assets are served from cache immediately and refreshed in the background; API and cross-origin requests are not intercepted | `sw.test.ts` |
| AC5 | `viewport.themeColor` is a hex string and `metadata` no longer carries `themeColor` | `layout-metadata.test.tsx` |
| AC6 | `generateMetadata` returns catalog-derived title/description per locale, plus `appleWebApp` and `icons.apple` | `layout-metadata.test.tsx` |
| AC7 | No user-facing string in `src/`, `public/`, or `messages/` matches `/wastewater|aguas residuales/i` | `message-parity.test.ts` + grep in gates |
| AC8 | `/offline` renders localized copy in both locales | `offline/__tests__/page.test.tsx` |

**SHOULD**

- ES/EN parity holds and no key carries an identical value in both catalogs unless it is a proper
  noun (`app.title`) — the leak that let `app.description` survive the s7.3 pass
- The offline page offers a retry affordance

**MUST NOT**

- Add any npm dependency
- Intercept `/api/*` or cross-origin requests in the worker
- Cache navigation responses for `/` or `/en` at install time
- Leave the source-text assertions in `sw.test.ts` in place alongside the behavioral ones
