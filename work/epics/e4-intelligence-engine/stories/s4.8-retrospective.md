# Retrospective: S4.8 — LLM Enrichment Verification + Visible Degradation

**Dates:** 2026-07-27 (single session)
**Estimated:** S (5 tasks) | **Actual:** S — 5 tasks, one transient provider hiccup, no rework

## Summary

Closed E3's long-descoped acceptance-gate item 3. The enrichment stack (built in E3, tested only
against mocks) now runs verified against a real model, and — the durable half — a degraded run is
no longer indistinguishable from a live one: `enrich()` returns a ground-truth
`EnrichmentOutcome(dataset, enriched)`, `/generate` surfaces `enriched: bool`, the persisted
`source` is honest (`procedural` vs `procedural+enrichment`), and an empty key logs a loud startup
WARNING. Real-model evidence recorded in `s4.8-progress.md`. Backend 308 → 331 tests.

## What went well
- **Gemba caught the real defect precisely:** the empty-key path returns 201 with `source=
  "procedural+enrichment"` and raw Faker names — a lie by construction. That framed the whole story.
- **Ground-truth over heuristic:** chose an explicit outcome object over sniffing `sector_description`
  NaN downstream. The heuristic would have re-created the anti-pattern the story exists to kill.
- **Contract migration in one commit** (T1+T2) per the design's legacy sweep — no broken intermediate
  where the caller type-errors. `mypy app/` at each task caught the unused `RawDataset` import.
- **Real model passed cleanly:** names changed to plausible Mexican companies; >20-client batch
  boundary confirmed (2 calls); 25/25 populated.

## What to improve
- **Free-tier flakiness is real:** first attempt hit `KeyError: 'choices'` (provider returned a body
  without `choices`). The `OpenRouterAdapter` assumes a well-formed success shape and would raise on
  an error payload. Out of scope here (s4.8 excludes adapter hardening) but worth a story — see below.
- **Reasoning-model tokens:** Nemotron Ultra spends budget on reasoning before JSON; the verify script
  had to bump `max_tokens` to 2048. Production enrichment should set this deliberately or use `:super`.
- **English descriptions:** the prompt doesn't pin a language; output came back in English for a
  Spanish-UI demo. Prompt-tuning (parked).

## Heutagogical Checkpoint
1. **What did I learn?** The most honest observability signal comes from the component that performed
   the work, not from inspecting its output shape afterward. A NaN-sniff is a guess; a returned flag is
   a fact.
2. **What would I change about the process?** I merged T1 and T2 into one commit mid-implementation
   (correctly, per the legacy sweep). The plan should have decomposed them as one task from the start
   when the design already declared they migrate together — the plan's task boundaries lagged the design.
3. **Framework improvements?** The graph/PRIME queries returned 0 results again (graph indexes the wrong
   root — known parking-lot item). Until rebuilt, `pattern add` accumulates knowledge nothing reads back.
4. **More capable of now?** Driving a full RaiSE story lifecycle (start→design→plan→implement→review) with
   TDD gates and honest-degradation design under a real external dependency.
