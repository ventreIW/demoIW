# s4.9 Scope — Score Persistence (IScoreRepository + adapter)

Status: **Active** — started 2026-07-27. Branch: `story/s4.9/score-persistence`.
Owner: Rodrigo (covering; originally Nano). Size: XS.

## In Scope
- `IScoreRepository` port in `app/ports/repositories.py` — `add_many(scores)` and
  `get_by_scenario(scenario_id)` (mirrors the existing repository ports).
- `SQLAlchemyScoreRepository` adapter in `app/adapters/persistence/`, using the existing
  `ScoreORM` and mappers.
- Container provider `get_score_repo` in `app/container.py`, mirroring `get_scenario_repo`.
- Unit tests: round-trip persistence (add_many → get_by_scenario), field fidelity, empty read.

## Out of Scope
- Wiring persistence into the scoring use case / endpoints (a scenario-scoring pipeline is its own
  concern; this story delivers the port + adapter the pipeline will consume).
- Any change to `Score` entity, `ScoreORM`, or the mappers — they already exist and are correct.
- `get_by_client` / update-in-place — add only if a consumer needs it (YAGNI); not required by the
  acceptance gate.
- Alembic migration authoring — the `scores` table/ORM already exists from E2.

## Done when
- [ ] `IScoreRepository` defines `add_many` and `get_by_scenario` as abstract methods.
- [ ] `SQLAlchemyScoreRepository` implements them against `ScoreORM` via the existing mappers.
- [ ] Scores persist and read back with value, category (enum), explanation, scored_at intact.
- [ ] `get_by_scenario` on an empty scenario returns `[]`, not an error.
- [ ] Container exposes `get_score_repo`.
- [ ] All new tests pass; ruff/format/mypy clean on touched files.
