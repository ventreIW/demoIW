# s4.10 Scope — Score Persistence Wiring

Status: **Active** — created 2026-07-27 from M4 finding (gate #1 unmet). Owner: Rodrigo. Size: S.
Branch: `story/s4.10/score-persistence-wiring`.

## In Scope
- `ScoreAndPersistScenario` use case (`app/application/use_cases/`): load the scenario's dataset,
  run `ScoreScenario`, persist `run.scores` via `IScoreRepository.add_many`; idempotent (skip if
  already persisted). Returns a small summary (scored_count, unscored_count).
- `POST /api/v1/scenarios/{id}/score` endpoint returning a `ScoreRunResponse`.
- Container provider `get_score_and_persist_use_case` wiring scenario_repo + score_repo.
- Tests: persists all clients (mocked scorer + in-memory DB), idempotent re-run, 404 on no data.

## Out of Scope
- Changing the prioritized endpoint to read persisted scores (keeps scoring live — separate concern).
- Replace-on-rescore semantics (E5 operations panel).
- Auto-scoring inside `/generate` (explicit `/score` step is clearer and matches the gate).
- Any change to `ScoreScenario`, `Score`, `ScoreORM`, mappers, or `IScoreRepository`.

## Done when
- [ ] `POST /{id}/score` persists a Score for every scored client; `get_by_scenario` returns them.
- [ ] Response reports scored + unscored counts.
- [ ] Re-calling does not create duplicate rows.
- [ ] 404 when the scenario has no dataset.
- [ ] Container exposes the use case; all new tests pass; ruff/format/mypy clean on touched files.
- [ ] Epic acceptance gate #1 ("every client in an active scenario has a persisted Score") satisfiable.
