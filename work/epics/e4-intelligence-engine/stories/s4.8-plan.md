## Tasks

### T1 — `EnrichmentOutcome`: `enrich()` reports whether the model ran (riskiest — contract change)
- **Files:** `app/application/services/llm_enrichment_service.py`, `tests/unit/test_llm_enrichment_service.py`
- **RED:** Update the 4 existing `enrich()` call sites to unpack `outcome.dataset`; add asserts —
  `outcome.enriched is True` when a batch succeeds, `is False` when all batches fail/degrade.
- **GREEN:** Add `@dataclass(frozen=True) EnrichmentOutcome(dataset: RawDataset, enriched: bool)`
  (co-located in the service module). Track `batches_enriched`; return
  `EnrichmentOutcome(dataset, enriched=batches_enriched > 0)`. Empty-clients early return → `enriched=False`.
- **REFACTOR:** Keep the loud length-mismatch fail intact.
- **Verify:** `rai gate check gate-tests --scope backend/tests/unit/test_llm_enrichment_service.py`
- **Size:** S · **Deps:** none · **AC:** MUST(enrich returns outcome)

### T2 — Honest `source` + `execute()` returns `enriched`
- **Files:** `app/application/use_cases/generate_dataset.py`, `tests/unit/test_generate_dataset.py`
- **RED:** `execute()` returns `enriched: bool`; `source == "procedural+enrichment"` when enriched,
  `"procedural"` when not. Update the `assert result is enriched_dataset` assertion accordingly.
- **GREEN:** Consume `EnrichmentOutcome`; set `scenario.source` from `outcome.enriched`; return the flag.
- **Verify:** `rai gate check gate-tests --scope backend/tests/unit/test_generate_dataset.py`
- **Size:** S · **Deps:** T1 · **AC:** MUST(honest source), MUST(execute reports enriched)

### T3 — `/generate` surfaces `enriched: bool`
- **Files:** `app/routers/scenarios.py`, `tests/test_scenarios_api.py`
- **RED:** `/generate` response includes `enriched`; `true` on mocked LLM success, `false` on mocked
  failure; endpoint still `201` in both cases (degradation preserved).
- **GREEN:** Add `GeneratedScenarioResponse(ScenarioSummary)` with `enriched: bool`; set it from
  `execute()`'s return in the endpoint.
- **Verify:** `rai gate check gate-tests --scope backend/tests/test_scenarios_api.py`
- **Size:** S · **Deps:** T2 · **AC:** MUST(enriched flag), MUST(201 preserved)

### T4 — Loud startup warning on empty key (independent)
- **Files:** `app/main.py`, `tests/test_main_startup.py` (new)
- **RED:** With `OPENROUTER_API_KEY=""`, `lifespan` emits a `WARNING` naming that enrichment is disabled
  and scenarios will contain raw Faker names. With a key set, no such warning.
- **GREEN:** Add the check in `lifespan()` after `setup_logging()`.
- **Verify:** `rai gate check gate-tests --scope backend/tests/test_main_startup.py`
- **Size:** XS · **Deps:** none (parallel with T1–T3) · **AC:** MUST(startup warning)

### T5 — Real-model verification pass (evidence, not assertion) — MANUAL INTEGRATION
- **Files:** `backend/scripts/verify_enrichment.py` (new)
- **Steps:** Script drives `LLMEnrichmentService` with 3 Faker-style names (no DB/server), prints
  before/after. Run against the free Nemotron model; then generate a **>20-client** scenario and confirm
  ≥2 LLM calls (batch boundary) and `enriched=true`. If JSON parsing is flaky on the reasoning model,
  swap `MODEL_DATA_ENRICHMENT` to `:super`/`:nano` (config-only) and note it.
- **Verify (observable):** enriched names ≠ Faker; `sector_description` populated + sector-appropriate;
  batching confirmed; **record the actual output in `s4.8-retrospective.md`.**
- **Size:** S · **Deps:** T1–T3 · **AC:** MUST(real call recorded), SHOULD(standalone script)
