# S4.8 Design — Verify LLM Enrichment + Make Degradation Visible

## Problem

E3 shipped the enrichment stack (`OpenRouterAdapter`, `LLMEnrichmentService`, prompt template) but
it has never run against a real model — only `respx` mocks. Worse, when enrichment fails or the key
is empty, the system **lies**: the batch degrades to raw Faker names with `sector_description=NaN`,
the scenario is still persisted with `source="procedural+enrichment"`, and `/generate` returns `201`
with no signal. A dead AI subsystem is currently indistinguishable from a live one.

## Value

After this story: (1) a real OpenRouter call is proven to produce plausible Mexican company names
distinct from Faker, recorded as evidence; (2) any degraded run is **observable** — a loud startup
warning when the key is empty, an `enriched: true|false` flag on the generate response, and an honest
`source` on the persisted scenario. This closes E3 acceptance-gate item 3 and de-risks the same
credential for E5 (comms) and E6 (NL query).

## Approach

Two durable code changes plus a verification pass. Graceful degradation is **preserved** — the
endpoint still succeeds; it simply stops pretending the AI ran.

1. **Ground-truth enrichment outcome.** `LLMEnrichmentService.enrich()` currently returns a bare
   `RawDataset`, discarding whether any batch actually succeeded. Change it to return a small frozen
   `EnrichmentOutcome(dataset, enriched)` where `enriched = (batches_enriched > 0)`. This is the
   truthful signal — not a downstream heuristic that sniffs `sector_description` for NaN (that would
   itself be "guessing whether the AI ran", the exact anti-pattern this story kills).
2. **Propagate honestly.** `GenerateDataset.execute()` consumes the outcome, sets
   `source="procedural+enrichment"` when enriched and `source="procedural"` when not, and returns the
   `enriched` boolean. The `/generate` endpoint returns a new `GeneratedScenarioResponse(ScenarioSummary)`
   carrying `enriched: bool`.
3. **Loud startup warning.** In `main.py` `lifespan()`, after `setup_logging()`, log a `WARNING` when
   `settings.OPENROUTER_API_KEY` is empty: enrichment disabled, scenarios will contain raw Faker names.
4. **Verification pass (evidence, not assertion).** Recreate the drafted smoke script
   (`backend/scripts/verify_enrichment.py`) that drives `LLMEnrichmentService` with three Faker-style
   names and prints before/after; run it against the free Nemotron model and against a >20-client
   scenario to confirm batching. Record observed output in the retrospective.

### Legacy sweep

`enrich() -> RawDataset` (V1, `llm_enrichment_service.py:40`) is superseded by `enrich() -> EnrichmentOutcome`.
No coexistence — the sole caller is `generate_dataset.py:44`. Deletion plan: migrate the caller and the
4 call sites in `test_llm_enrichment_service.py` (`.dataset` unpack) in the same commit as the signature
change. Net-new: `EnrichmentOutcome`, `GeneratedScenarioResponse`, startup warning, verify script.

### Lean gates

- **KISS/MVP:** smallest honest change — one new value object, one new response field, one warning. No
  retry/config/telemetry work (that stays parked, per scope Out-of-Scope).
- **DRY:** reuses existing `OpenRouterAdapter`, batching, and prompt template unchanged.
- **YAGNI:** no cost tracking, no prompt tuning, no `enriched` persistence beyond the honest `source`.
- **Drift (AG2/AG4):** no clone amplification; change is confined to the enrichment path (≤5 modules,
  clear coupling). No `drift-hotspots.json` present — check skipped.
- **Supply chain:** no new dependencies (httpx/pydantic/fastapi already established). N/A.

### `EnrichmentOutcome`
```python
@dataclass(frozen=True)
class EnrichmentOutcome:
    dataset: RawDataset
    enriched: bool   # True iff at least one batch was enriched by the model
```

## Acceptance Criteria

Refines the Gherkin in `s4.8-story.md`.

- **MUST** `enrich()` returns `EnrichmentOutcome`; `enriched` is `True` iff ≥1 batch succeeded.
- **MUST** `/generate` response includes `enriched: bool`; `false` on empty-key/failed enrichment.
- **MUST** persisted `source` is `"procedural"` when not enriched, `"procedural+enrichment"` when enriched.
- **MUST** empty `OPENROUTER_API_KEY` logs a `WARNING` at startup.
- **MUST** graceful degradation preserved — `/generate` still returns `201` when the LLM fails.
- **MUST** a real OpenRouter call produced names differing from Faker + populated `sector_description`,
  observed and recorded (evidence, incl. a >20-client batch boundary).
- **SHOULD** the verify script runs standalone (no DB/server) for repeatable manual checks.
- **MUST NOT** commit any credential; **MUST NOT** silently pad/truncate a mismatched LLM batch (existing
  loud-fail behavior retained).
