> This file exists so the completion audit resolves cleanly and so a future reader looking for
> `s4.5-api-design.md` is sent to the right place rather than concluding the design was
> skipped. Created 2026-08-20 during the project-completion review, which initially flagged
> s4.5-API as missing a design — a false positive.

## Why one design across two stories was correct here

The split was along an implementation seam, not a design seam. The formula half owns the
value objects (`PrioritizedCase`, `PrioritizedPortfolio`), the priority-value definition and
the Pareto rule; the API half owns transport, query parameters, sorting and filtering over
those objects. Designing the transport separately would have meant either duplicating the
contract or inventing a second one.

The retrospective records that this worked: *"Contract-first design worked. The endpoint was
built against the value objects from `5d8980f` (T1). No rework on the contract."*
