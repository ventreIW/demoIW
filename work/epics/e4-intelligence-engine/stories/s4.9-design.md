# S4.9 Design — Score Persistence (IScoreRepository + adapter)

## Problem
The scoring model (s4.3) produces `Score` objects but nothing persists them. The `Score` entity,
`ScoreORM` (table `scores`), and both mappers already exist from E2 — the only gap is a repository
port + adapter to save and read them back. Without it, the epic acceptance gate ("every client has a
persisted Score") and M1 ("scores persist and read back via IScoreRepository") cannot be met.

## Value
A durable, port-based read/write path for scores that panels, prioritization, and the E2E checkpoint
consume — closing the persistence half s4.3 deliberately deferred.

## Approach
Mirror the existing `SQLAlchemyClientRepository` exactly (it already has `add_many` +
`get_by_scenario_id`). No new domain, ORM, mapper, or migration — all present.

### Components affected
| Component | Change | Purpose |
|---|---|---|
| `app/ports/repositories.py` | modify | Add `IScoreRepository` ABC: `add_many`, `get_by_scenario` |
| `app/adapters/persistence/sqlalchemy_score_repo.py` | create | `SQLAlchemyScoreRepository` over `ScoreORM` + existing mappers |
| `app/container.py` | modify | Add `get_score_repo` provider mirroring `get_scenario_repo` |
| `tests/unit/test_score_repository.py` | create | Round-trip, fidelity, empty-read |

### Legacy sweep
Net-new port + adapter. No V1 superseded — `IScoreRepository` does not exist yet; `Score`/`ScoreORM`/
mappers are reused unchanged. Nothing orphaned.

### Lean gates
- **KISS/YAGNI:** only `add_many` + `get_by_scenario` (the acceptance gate's needs). No `get_by_client`,
  no update-in-place, no `add` single unless a consumer appears.
- **DRY:** reuses `score_domain_to_orm` / `score_orm_to_domain`; copies the proven client-repo shape.
- **Storage-migration gate:** N/A — not replacing a storage mechanism; the table already exists.
- **Design choice:** unlike clients (server-assigned ids), a `Score` carries its own id from the scorer,
  so the adapter persists `domain.id` as-is (via the existing mapper) rather than reassigning.

## Examples
```python
class IScoreRepository(ABC):
    @abstractmethod
    async def add_many(self, scores: list[Score]) -> list[Score]: ...
    @abstractmethod
    async def get_by_scenario(self, scenario_id: UUID) -> list[Score]: ...
```
```python
# adapter (mirrors SQLAlchemyClientRepository)
async def add_many(self, scores: list[Score]) -> list[Score]:
    orms = [score_domain_to_orm(s) for s in scores]
    self._session.add_all(orms)
    await self._session.commit()
    return [score_orm_to_domain(o) for o in orms]

async def get_by_scenario(self, scenario_id: UUID) -> list[Score]:
    result = await self._session.execute(
        select(ScoreORM).where(ScoreORM.scenario_id == str(scenario_id))
    )
    return [score_orm_to_domain(o) for o in result.scalars()]
```
```python
# usage
repo = SQLAlchemyScoreRepository(session)
await repo.add_many([score_a, score_b, score_c])
scores = await repo.get_by_scenario(scenario_id)   # -> 3 Score objects, fields intact
```

## Acceptance Criteria
References Gherkin in `s4.9-story.md`.
- **MUST** `IScoreRepository` declares `add_many` + `get_by_scenario` (abstract).
- **MUST** adapter persists then reads back scores with value, category (enum), explanation, scored_at intact.
- **MUST** `get_by_scenario` on an empty scenario returns `[]`.
- **MUST** container exposes `get_score_repo`.
- **MUST NOT** modify `Score`, `ScoreORM`, or the mappers.
