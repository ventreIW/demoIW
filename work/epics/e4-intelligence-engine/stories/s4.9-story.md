# Story: Score Persistence — IScoreRepository + SQLAlchemy adapter

## User Story
As the **collectability engine**,
I want **computed scores persisted and readable through a repository port**,
so that **every client in an active scenario has a durable Score (value, category,
explanation) that panels and prioritization can read back — not just an in-memory result.**

## Acceptance Criteria

### Scenario: Persist and read back scores for a scenario
```gherkin
Given a set of Score domain objects for clients in a scenario
When they are saved through IScoreRepository.add_many
And the scores for that scenario are fetched through get_by_scenario
Then every saved score is returned with value, category, and explanation intact
```

### Scenario: Round-trip fidelity through the ORM
```gherkin
Given a Score with a known score_value, category, and explanation
When it is persisted and re-read
Then score_value, category (enum), explanation and scored_at match the original
```

### Scenario: Empty scenario reads back empty
```gherkin
Given a scenario with no persisted scores
When get_by_scenario is called
Then an empty list is returned (not an error)
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|---|---|---|
| 3 Score objects (scenario S) | `add_many` then `get_by_scenario(S)` | 3 scores, fields intact |
| `ScoreCategory.HIGH`, value 82.5 | persist + re-read | category==HIGH, value==82.5 |
| scenario with no scores | `get_by_scenario` | `[]` |

## Notes
- **Already exists (E2):** `Score` entity (`domain/entities/score.py`), `ScoreORM` (table `scores`),
  and both mappers (`score_orm_to_domain`, `score_domain_to_orm`) in `adapters/persistence/mappers.py`.
- **This story builds only:** `IScoreRepository` port (absent from `ports/repositories.py`), the
  `SQLAlchemyScoreRepository` adapter, and a container provider — mirroring the existing repositories.
- Delivers epic acceptance-gate items: "every client in an active scenario has a persisted Score" and
  M1 "scores persist and read back via IScoreRepository".
- s4.3 built the model without persistence and explicitly left it to s4.9.
