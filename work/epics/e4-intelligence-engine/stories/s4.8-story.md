# Story: Verify LLM Enrichment Against a Real Model + Visible Degradation

## User Story
As a **developer preparing the demo**,
I want **the AI enrichment path verified against a real OpenRouter model, and any degraded run made visibly distinguishable from a working one**,
so that **nobody presents raw Faker company names believing the AI ran — a dead subsystem must never look identical to a live one.**

## Acceptance Criteria

### Scenario: Enrichment runs against the real model (happy path)
```gherkin
Given OPENROUTER_API_KEY is configured and MODEL_DATA_ENRICHMENT points at a valid model
When a scenario is generated
Then the returned company names differ from the procedural Faker input names
And each client has a populated, sector-appropriate sector_description
And the generate response reports enriched: true
```

### Scenario: Batching crosses the 20-client boundary
```gherkin
Given enrichment is configured and a scenario with more than 20 clients
When the scenario is generated
Then the enrichment service issues more than one LLM call
And every client across all batches is enriched
```

### Scenario: Missing key is loud, not silent
```gherkin
Given OPENROUTER_API_KEY is empty
When the backend starts up
Then a warning is logged that enrichment is disabled
And when a scenario is generated the endpoint still returns 201
And the generate response reports enriched: false
```

### Scenario: A failed LLM call degrades visibly (edge case)
```gherkin
Given OPENROUTER_API_KEY is configured but the LLM call fails
When a scenario is generated
Then the endpoint still returns 201 (graceful degradation preserved)
And the generate response reports enriched: false
And the company names remain the raw Faker values
```

## Examples (Specification by Example)

| Input (key / clients) | Action | Expected Output |
|---|---|---|
| key set, 5 clients | generate scenario | names ≠ Faker; `sector_description` set; `enriched: true`; 1 LLM call |
| key set, 45 clients | generate scenario | all 45 enriched; `enriched: true`; ≥ 3 LLM calls (batch=20) |
| key empty | backend start + generate | startup WARN logged; `201`; `enriched: false`; names == Faker |
| key set, provider 500s | generate scenario | `201`; `enriched: false`; names == Faker |
