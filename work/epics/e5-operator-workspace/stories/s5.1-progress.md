## What T6 caught that the unit tests could not

Both are the same failure mode E4's M4 checkpoint was created for: a mock and its
subject agreeing with each other and both being wrong.

1. **`category` is lowercase.** The live payload serializes `ScoreCategory` as `"high"`,
   not `"High"`. The TS type, the component's lookup maps, and the test fixture all
   shared the capitalized assumption, so `CATEGORY_KEY[row.category]` resolved to
   `undefined` and the badge would have rendered blank in production. Every test passed.
   Fixed, and a test now enumerates all three real values so a recurrence fails loudly.

2. **`/cases` was unreachable.** `middleware.ts` redirected every non-`/scenarios` route
   to `/scenarios` unless an `active_scenario_id` cookie was present — and nothing in the
   app ever set that cookie; it was only ever read. The guard therefore fired
   unconditionally. It went unnoticed because the sidebar's only working link was
   `/scenarios` itself. s5.1 is the first story to add a second route; s5.2–s5.5 add four
   more. Guard removed (see the file comment for why it was not reinstated with a
   working cookie).
