# S5.3 Design — Contact Result + Status Update (→ Rescore)

## Problem
The operator needs to record a contact result (e.g., "promise_to_pay", "paid", "no_answer") on a case detail page. This should persist the contact result and trigger the existing E4 rescore endpoint so the operator sees updated scores immediately.

## Value
Connects the operator's daily action (recording contact) to the intelligence engine (E4 rescore). First end-to-end operator → intelligence loop.

## Approach
Thin orchestration — no new scoring or persistence logic. Reuses:
- `ContactResultORM` + mappers (E2, exists)
- `ContactResultType` enum (E4, exists)
- `RescoreScenario.execute` use case (E4 s4.6, exists)

New components:
1. `IContactResultRepository` port + `SQLAlchemyContactResultRepository` adapter
2. `RecordContactResult` use case: persist ContactResult → call RescoreScenario.execute → return updated portfolio
3. `POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/contact-result` endpoint
4. Container provider wiring

### Components affected
| Component | Change | Purpose |
|-----------|--------|---------|
| `app/ports/repositories.py` | add `IContactResultRepository` | Port for contact result persistence |
| `app/adapters/persistence/sqlalchemy_contact_result_repo.py` | create | Adapter over `ContactResultORM` |

| `app/container.py` | add provider | Wire repos + rescore use case |

## Endpoint Design

```
POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/contact-result
```

**Request:**
```json
{
  "contact_result": "promise_to_pay",
  "notes": "Client will pay Friday"
}
```

**Response (201):** `PrioritizedPortfolioResponse` (same as rescore endpoint) — the updated portfolio with adjusted scores.

**Errors:**
- 404: scenario or client not found
- 422: invalid `contact_result` (not in `ContactResultType`)

## Use Case: `RecordContactResult`

```python
class RecordContactResult:
    def __init__(
        self,
        contact_result_repo: IContactResultRepository,
        scenario_repo: IScenarioRepository,
        client_repo: IClientRepository,
        rescore_use_case: RescoreScenario,
    ) -> None:
        ...

    async def execute(
        self,
        scenario_id: UUID,
        client_id: UUID,
        contact_result: ContactResultType,
        notes: str | None,
    ) -> PrioritizedPortfolio:
        # 1. Verify scenario exists
        scenario = await self._scenario_repo.get_by_id(scenario_id)
        if scenario is None:
            raise EntityNotFoundError("Scenario", str(scenario_id))

        # 2. Verify client exists
        client = await self._client_repo.get_by_id(client_id)
        if client is None:
            raise EntityNotFoundError("Client", str(client_id))

        # 3. Persist ContactResult
        contact_result_entity = ContactResult(
            id=uuid4(),
            client_id=client_id,
            communication_id=None,  # s5.3: no communication yet; s5.4 links them
            result_type=contact_result,
            notes=notes,
            recorded_at=datetime.now(UTC),
        )
        await self._contact_result_repo.add(contact_result_entity)

        # 4. Trigger rescore (reuses E4 s4.6)
        portfolio = await self._rescore_use_case.execute(
            scenario_id=scenario_id,
            client_id=client_id,
            contact_result=contact_result.value,  # string for RescoreScenario
            repo=self._scenario_repo,
        )
        return portfolio
```

## Idempotency / Audit
- Each contact result is a **new row** (append-only audit trail). No dedup needed.
- `communication_id` is nullable for now; s5.4/s5.5 will link when a communication is generated.
