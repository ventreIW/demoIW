# S5.5 Scope — Communications Generator Frontend Flow

**Status:** Active | **Size:** S | **Owner:** Renor | **Branch:** `story/s5.5/communications-generator-frontend`

## In Scope
- CommunicationsGenerator component: channel/tone selector dropdowns, "Generate draft" button, editable text area, "Send" button
- Integration into CaseDetail page: new "Communications" section with Generate/Send flow
- API client: `POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/communications` (generate draft) in `lib/api/cases.ts`
- API client: `PATCH …/communications/{comm_id}/send` (send draft) in `lib/api/cases.ts` — backend endpoint may need to be added
- Editable draft: text area pre-filled with generated draft, user can modify before sending
- Channel/tone selector: dropdowns for Channel enum (email, phone, whatsapp) and Tone enum (formal, firm, urgent)
- Send confirmation dialog: modal with "Confirm" / "Cancel" before status transition
- Loading states: spinner/disabled state for generate and send buttons
- Error handling: display validation errors (422) and server errors (502, 500) inline
- Success feedback: toast or inline message after successful send
- i18n keys: `es.json` / `en.json` for all new labels, options, status messages
- Tests: Vitest unit tests for the CommunicationsGenerator component (mock API, verify render/generate/edit/send/error states)

## Out of Scope
- Backend generate endpoint (already done by s5.4 — merged to main)
- Real message delivery (email/SMS/WhatsApp) — "send" = status `draft → sent` + audit row only
- Multi-operator auth / roles (demo is single-operator)
- Email/WhatsApp or any real transport integration
- Contact result form changes (s5.3 owns it)
- Historical communications list improvements (s5.2 owns the read-only display)

## Done When
- [ ] CommunicationsGenerator component renders with channel/tone selector, Generate button, editable text area, Send button
- [ ] Selecting channel and tone and clicking Generate calls POST /communications and displays draft in editable area
- [ ] Draft text area is editable and reflects user changes
- [ ] Clicking Send shows confirmation dialog; confirming transitions status to "sent"
- [ ] Cancelling send leaves draft unchanged
- [ ] API errors (generate/send) show inline error messages with retry option
- [ ] Loading states shown during generate and send API calls
- [ ] Component integrated into CaseDetail page as a new section
- [ ] All Vitest tests pass; typecheck + lint + format clean
- [ ] i18n keys added for both es/en
- [ ] Backend send endpoint available (PATCH …/communications/{id}/send) — confirmed during design
