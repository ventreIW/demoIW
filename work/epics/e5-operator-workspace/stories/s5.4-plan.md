### T4: Implement GenerateCommunicationDraft Use Case

**Description:** Create `GenerateCommunicationDraft` in `app/application/use_cases/generate_communication_draft.py`:
- Request/Response dataclasses with `scenario_id`, `client_id`, `channel`, `tone`
- Inject all repos: `IScenarioRepository`, `IClientRepository`, `IInvoiceRepository`, `IPaymentRepository`, `IScoreRepository`, `ICommunicationRepository`
- Inject `CommunicationDraftService`
- `execute()`:
  1. Verify scenario exists (404)
  2. Verify client exists & belongs to scenario (404)
  3. Fetch case aggregate (invoices, payments, score, existing comms) — reuse S5.2 logic
  4. Build case detail context
  5. Call `draft_service.generate(case_detail, channel, tone)`
  6. Persist `Communication(draft_text=..., channel, tone, status=DRAFT, created_at=now)`
  7. Return `GenerateCommunicationDraftResponse(communication=persisted)`

**Files to create/modify:**
- `app/application/use_cases/generate_communication_draft.py` (new)

**TDD Cycle:**
1. **RED:** Write test first (see T5)
2. **GREEN:** Implement use case orchestrating repos + draft_service
3. **REFACTOR:** Extract case aggregate fetching to helper (reuse S5.2 pattern)

## Gate Policy (per skill)

| When | Command | Scope |
|------|---------|-------|
| Per task | `rai gate check gate-tests --scope <test_dir>/` | Only tests for the changed module |
| Per task | `rai gate check gate-lint` | Full project (fast) |
| Per task | `rai gate check gate-format` | Full project (fast) |
| Per task | `rai gate check gate-types` | Full project |
| End of story | `rai gate check gate-tests --scope packages/<pkg>/` | Changed package only — NOT full suite |
| MR creation | `/rai-mr-create` | Full suite — the ONLY place where unscoped tests run |

**NEVER run test commands directly** (e.g. `uv run pytest`) — always use `rai gate check`. If `rai gate check` fails, use `pytest` directly as fallback.
