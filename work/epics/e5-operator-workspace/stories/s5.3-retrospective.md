## What went well
- **Existing patterns followed** — reused `useState` pattern from `GenerateScenarioForm`/`CsvUpload`, reused `Select`/`Button` UI components, matched existing i18n structure
- **Risk mitigation worked** — the plan flagged the Base UI Select JSDOM issue, which saved debugging time by using `fireEvent.click` + `vi.waitFor` instead of fighting the Select popup
- **Backward compatible integration** — `scenarioId`/`clientId` made optional on `CaseDetailView`; existing tests continue without modification
- **Clean linear execution** — T1 → T2 → T3 with no blockers, no rework, no circular dependencies

## What to improve
- **Test mock hoisting complexity** — `vi.mock` + `vi.hoisted()` + shared mock across tests required iteration. The initial approach with per-test `vi.hoisted()` caused "Identifier already declared" errors. A single shared mock with `mockReset()` in `beforeEach` was the correct pattern.
- **`notes: ''` vs `notes: undefined`** — the component converts empty string to `undefined` via `notes || undefined`. The test expectation initially expected `''` instead of `undefined`. A more explicit contract in the design would have avoided the mismatch.

## Heutagogical Checkpoint
1. **What did I learn?**
   - Base UI Select in JSDOM: SelectContent items are in a Portal — not rendered until popup opens. Cannot test dropdown options with `getByText`; use `getAllByText` for elements that appear in both heading and button.
   - `vi.mock` hoisting in vitest: all `vi.mock()` calls are hoisted to the top of the file. Mock variables must use `vi.hoisted()` to be defined before the mock factory runs. A single shared mock with `mockReset()` in `beforeEach` is the cleanest pattern.
   - `fireEvent.click` on a submit button reliably triggers React's `form.onSubmit` handler in JSDOM. `fireEvent.submit` on the form element also works but `click` is more idiomatic.

2. **What would I change about the process?**
   - The plan's risk documentation (Base UI Select JSDOM issue) was valuable — it saved debugging time. Continue flagging known test environment quirks in the risk section.
   - The `notes` field contract (empty string → `undefined` via `notes || undefined`) should be documented in the design's data structures section to avoid test expectation mismatches.
