## Tasks

### T1 — `IContactResultRepository` port + `SQLAlchemyContactResultRepository` adapter
- **Files:** `app/ports/repositories.py`, `app/adapters/persistence/sqlalchemy_contact_result_repo.py` (new), `tests/unit/test_contact_result_repository.py` (new)
- **RED:** With an in-memory SQLite DB, `add()` persists a `ContactResult` and `get_by_client_id()` returns it. `get_by_client_id()` returns empty list for unknown client.
- **GREEN:** Implement port + adapter using existing `ContactResultORM` + mappers (`contact_result_orm_to_domain`, `contact_result_domain_to_orm`).
- **Verify:** `rai gate check gate-tests --scope tests/unit/test_contact_result_repository.py`; `rai gate check gate-lint`; `rai gate check gate-format`; `rai gate check gate-types`
- **Size:** S · **Deps:** none

### T2 — `RecordContactResult` use case
- **Files:** `app/application/use_cases/record_contact_result.py` (new), `tests/unit/test_record_contact_result.py` (new)
- **RED:** With mocked repos (scenario, client, contact_result) and a stubbed `RescoreScenario` returning a known `PrioritizedPortfolio`, `execute(scenario_id, client_id, contact_result, notes)`:
  - Persists a `ContactResult` via repo
  - Calls `RescoreScenario.execute` with correct args
  - Returns the portfolio
  - Raises `EntityNotFoundError` for missing scenario/client
- **GREEN:** Implement use case per design. Accept `ContactResultType` enum, convert to string for rescore call.
- **Verify:** `rai gate check gate-tests --scope tests/unit/test_record_contact_result.py`; `rai gate check gate-lint`; `rai gate check gate-format`; `rai gate check gate-types`
- **Size:** S · **Deps:** T1

### T3 — `POST /{scenario_id}/clients/{client_id}/contact-result` endpoint + container provider
- **Files:** `app/routers/cases.py` (add endpoint), `app/container.py` (add `get_record_contact_result_use_case`), `tests/test_contact_result_endpoint.py` (new)
- **RED:** With dependency overrides stubbing the use case:
  - `POST /api/v1/scenarios/{id}/clients/{cid}/contact-result` with valid payload → 201, returns `PrioritizedPortfolioResponse`
  - Invalid `contact_result` (not in enum) → 422
  - Unknown scenario/client → 404
- **GREEN:** Add `ContactResultRequest` model, endpoint catching `EntityNotFoundError` → 404, enum validation → 422, container provider wiring all repos + `RescoreScenario`.
- **Verify:** `rai gate check gate-tests --scope tests/test_contact_result_endpoint.py`; `rai gate check gate-lint`; `rai gate check gate-format`; `rai gate check gate-types`
- **Size:** S · **Deps:** T1, T2

### T4 — Manual integration test (final task)
- **Action:** Start backend (`uv run uvicorn app.main:app --reload` from `backend/`), create a scenario via `POST /api/v1/scenarios/generate`, get a client from `GET /api/v1/scenarios/{id}/prioritized`, call `POST /api/v1/scenarios/{id}/clients/{cid}/contact-result` with `{"contact_result": "promise_to_pay"}`, verify:
  - Response is 201 with portfolio
  - The specific client's score increased by +10 (per `_CONTACT_RESULT_DELTA`)
  - `GET /api/v1/scenarios/{id}/clients/{cid}/contact-results` (if exists) or check DB for `ContactResult` row
- **Verify:** Manual — observable behavior
- **Size:** XS · **Deps:** T1, T2, T3

## Execution Order
`T1 ──▶ T2 ──▶ T3 ──▶ T4` (linear, acyclic)

| Risk | Mitigation |
|------|------------|
| `RescoreScenario` expects string, not enum | Convert `contact_result.value` in use case |
| `communication_id` nullable in ORM | Set to `None` in use case; s5.4 will link |
| Port already exists but different signature | Check `app/ports/repositories.py` first — add method only |
| Enum validation at endpoint | Use `ContactResultType` in Pydantic model; FastAPI auto-validates |
