# Story: Contact Result + Status Update (→ Rescore)

## User Story
As the **collections operator (P-01)**,
I want **to record a contact result and update the client's status, which triggers an automatic rescore of the portfolio**,
so that **the prioritized case list reflects the latest contact outcome immediately**.

## Context (why this story exists)
E4 s4.6 delivered the rescore endpoint (`POST /api/v1/scenarios/{id}/clients/{client_id}/rescore`). E5 s5.2 delivered the case detail page. This story wires the "Record Contact" action on the case detail: persist the contact result, update status, and call the rescore endpoint so the operator sees updated scores without leaving the page.

## Acceptance Criteria

### Scenario: Record a contact result and trigger rescore
```gherkin
Given an active scenario with scored clients
And the operator is viewing a case detail page
When the operator selects a contact result (e.g., "promise_to_pay") and clicks "Record Contact"
Then a ContactResult is persisted with result_type, notes, timestamp, and operator
And the client's status is updated
And the E4 rescore endpoint is called with the contact_result
And the updated prioritized portfolio is returned with the adjusted score
And the case detail UI reflects the new score
```

### Scenario: Invalid contact result type
```gherkin
Given an active scenario
When the operator submits a contact result not in ContactResultType
Then the endpoint returns 422 with validation error
```

### Scenario: Client not found
```gherkin
Given an active scenario
When the operator records a contact for a non-existent client_id
Then the endpoint returns 404
```

## Examples (Specification by Example)

| Input | Action | Expected |
|-------|--------|----------|
| scenario_id, client_id, contact_result="promise_to_pay", notes="Client will pay Friday" | POST /contacts/result | 201; ContactResult persisted; rescore called; portfolio returned with +10 score delta |
| same client, contact_result="paid" | POST /contacts/result again | 201; new ContactResult row; rescore called; score delta 0 (paid) |
| contact_result="invalid_type" | POST /contacts/result | 422 |

## Notes
- Reuses existing `RescoreScenario` use case (E4 s4.6) — no new scoring logic.
- New: `IContactResultRepository` port + `SQLAlchemyContactResultRepository` adapter.
- New: `RecordContactResult` use case orchestrating: persist contact_result → update client status → call `RescoreScenario.execute`.
- New: `POST /api/v1/contacts/result` endpoint (or nested under scenario/client).
- ContactResultType enum: `promise_to_pay` (+10), `partial_payment` (+5), `no_answer` (0), `disputed` (0), `paid` (0) — per s4.6 `_CONTACT_RESULT_DELTA`.
- Idempotency: each contact is a new row (audit trail); no dedup needed.
