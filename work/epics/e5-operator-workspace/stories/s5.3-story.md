# Story: Contact Result + Status Update (→ Rescore)

## User Story
As a **collections operator (P-01)**,
I want to **record a contact result and update the client's status**,
so that **the E4 rescore endpoint is triggered and the client's score reflects the latest interaction**.

## Acceptance Criteria

### Scenario: Record a contact result and trigger rescore
```gherkin
Given an active scenario with a client that has a current score
And the operator selects a contact result type (e.g., "promise_to_pay")
When the operator records the contact result via POST /api/v1/clients/{client_id}/contact-result
Then a ContactResult is persisted with the result type, notes, and timestamp
And the client's status is updated
And the E4 rescore endpoint (POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/rescore) is called
And the response includes the updated prioritized portfolio with the client's new score
```

### Scenario: Record contact result for unknown client
```gherkin
Given a client_id that does not exist
When the operator records a contact result
Then the endpoint returns 404 (client not found)
```

### Scenario: Record contact result with invalid result type
```gherkin
Given a valid client_id
When the operator submits an invalid contact_result_type
Then the endpoint returns 422 (validation error)
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| client_id=uuid, result_type="promise_to_pay", notes="Client will pay Friday" | POST /clients/{id}/contact-result | 201; ContactResult persisted; rescore triggered; updated portfolio returned |
| client_id=unknown, result_type="promise_to_pay" | POST /clients/{id}/contact-result | 404 |
| client_id=valid, result_type="invalid_type" | POST /clients/{id}/contact-result | 422 |

## Notes
- Reuses existing `ContactResultORM` + mappers (E2), `ContactResultType` enum
- Reuses existing E4 rescore endpoint `POST /api/v1/scenarios/{id}/clients/{client_id}/rescore` (s4.6)
- Requires new `IContactResultRepository` port + `SQLAlchemyContactResultRepository` adapter
- New use case: `RecordContactResult` (orchestrates: persist contact result → update status → call rescore)
- New endpoint: `POST /api/v1/clients/{client_id}/contact-result`
- Owner: Nano (backend only; frontend action in s5.3 frontend)
