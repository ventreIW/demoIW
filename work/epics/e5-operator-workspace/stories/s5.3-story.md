# Story: Contact Result Form (Frontend)

## User Story
As the **collections operator (P-01)** viewing a case detail,
I want **to record a contact result via a form on the case detail page**,
so that **the interaction outcome is persisted and the score reflects the latest contact**.

## Context (why this story exists)
E5 s5.2 delivered the case detail page. The backend endpoint (`POST /api/v1/scenarios/{id}/clients/{client_id}/contact-result`) was built by Nano in the previous s5.3 iteration and merged to main. This story wires the frontend form: a dropdown for contact result type, a notes textarea, and a Record button that calls the existing endpoint and updates the displayed score.

## Acceptance Criteria

### Scenario: Record a contact result — success
```gherkin
Given the operator is viewing a case detail page
When the operator selects a contact result type, enters notes, and clicks "Record Contact"
Then a POST request is sent to /api/v1/scenarios/{id}/clients/{client_id}/contact-result with { contact_result, notes }
And the form shows a success confirmation
And the score display updates to reflect the new value from the response
```

### Scenario: Record a contact result — validation error
```gherkin
Given the operator is viewing a case detail page
When the operator submits an invalid contact result type
Then the form shows an inline validation error message
And the button remains enabled
```

### Scenario: Record a contact result — network error
```gherkin
Given the operator is viewing a case detail page
When the API returns a 422 or 500 error
Then the form shows an inline error message with the error details
And the button becomes enabled again
```

### Scenario: Form loading state
```gherkin
Given the operator has submitted the form
When the request is in flight
Then the Record button is disabled and shows a loading indicator
And the form inputs are disabled
```

## Examples (Specification by Example)

| Input | Action | Expected |
|-------|--------|----------|
| result_type="promise_to_pay", notes="Client will pay Friday" | Click "Record Contact" | 201 → success toast + score updated |
| result_type="invalid" | Click "Record Contact" | 422 error message shown inline |
| network offline | Click "Record Contact" | Error message: "Failed to record contact result" |
| result_type="no_answer", notes="" | Click "Record Contact" | 201 → success (notes optional) |

## Notes
- Backend endpoint already exists: `POST /api/v1/scenarios/{id}/clients/{client_id}/contact-result` (merged to main)
- Request body: `{ "contact_result": "promise_to_pay", "notes": "..." }` — notes is optional
- Response (201): `RecordContactResultResponse` with updated portfolio
- ContactResultType enum values: `promise_to_pay`, `partial_payment`, `no_answer`, `disputed`, `paid`
- Scenario ID and client ID are available from the case detail page route params
- The score section in CaseDetail should be updated to reflect the new score after success
