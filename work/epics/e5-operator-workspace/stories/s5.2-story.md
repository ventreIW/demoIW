# Story: Case Detail View (+ Case-Aggregate Read API)

## User Story
As the **collections operator (P-01)**,
I want **to open a case from the prioritized list and see every relevant detail on one screen**,
so that **I can assess the account at a glance — profile, invoices, payment history, and past communications — without switching tools or hunting through raw data.**

## Acceptance Criteria

### Scenario: Case detail shows client profile + invoices + payments + comms
```gherkin
Given I am viewing the operations panel case list
When I click on a row (or tap the detail-link for a client)
Then a case detail view opens for that client
And the view shows:
  - Client profile (name, sector, payment pattern)
  - All invoices (folio, amount, due date, days overdue, status)
  - Payment history (amount, date, method)
  - Communications log (draft text, channel, tone, status, created_at)
```

### Scenario: Aggregate REST endpoint returns full case state
```gherkin
Given a client exists under an active scenario
When GET /api/v1/scenarios/{scenarioId}/clients/{clientId} is called
Then the API returns a CaseDetail response with
  - Client profile fields
  - Invoices array sorted by due_date desc
  - Payments array sorted by payment_date desc
  - Communications array sorted by created_at desc (empty when none exist)
  - Score (value, category, explanation) if available
```

### Scenario: 404 for unknown client or scenario
```gherkin
Given a scenario or client ID that does not exist
When GET /api/v1/scenarios/{scenarioId}/clients/{clientId} is called
Then the API returns a 404 error
```

### Scenario: Detail page shows loading + error states
```gherkin
Given the aggregate API is still loading
When the detail page renders
Then a loading indicator is shown

Given the aggregate API returns an error (or is unreachable)
When the detail page renders
Then a friendly error state is shown, not a crash or blank page
```

### Scenario: Page is ES-first via next-intl
```gherkin
Given the locale is "es"
When the case detail page renders
Then all labels, headings, and status text come from next-intl messages (no hardcoded strings)
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| Client ID `c001` under scenario `s-active` | GET `/scenarios/s-active/clients/c001` | 200: CaseDetail with profile, 3 invoices, 5 payments, 1 comm |
| Client ID `nope` under scenario `s-active` | GET `/scenarios/s-active/clients/nope` | 404: "Client not found" |
| Scenario ID `nope` | GET `/scenarios/nope/clients/c001` | 404: "Scenario not found" |
| Viewing case for client with no comms | Open case detail | Profile + invoices + payments sections render; comms section shows "Sin comunicaciones" |

## Notes
- **This is the hub story** — s5.3 (contact result) and s5.4 (comms generator) depend on the case detail existing.
- Follow the `lib/api` fetch pattern established by s5.1 (`prioritized.ts`).
- New aggregate endpoint composes over existing repos (Client, Invoice, Payment) without new persistence.
- Score for the client comes from `IScoreRepository.get_by_scenario` (already exists via s4.9).
- Reuses `MainLayout` and next-intl patterns from s5.1.
- Keep `es.json`/`en.json` key parity (E4 verified 56/56 — do not regress).
