### T6 — Manual integration test (running software)
**Size:** S · **Depends on:** T5 · **AC:** AC-4, AC-5, AC-8

Not a unit test — E4's M4 lesson is that mocked green tests hide broken seams. Drive the real thing.

1. `cd backend && .venv/bin/uvicorn app.main:app --reload`
2. `cd frontend && npm run dev`
3. Generate a scenario (retail, 100 clients, seed 42), activate it.
4. Open `/es/cases` — confirm rows carry **real client names** (not UUIDs) and non-zero days overdue.
5. `curl "…/prioritized?days_overdue_min=30"` — confirm a non-empty **subset**, the behaviour that
   was broken before this story.
6. Switch to `/en/cases` — no missing-key errors, no Spanish leakage in English UI chrome.
7. Deactivate all scenarios → confirm `noActiveScenario` state.
- **Verification:** full gates — `./scripts/test.sh`, `./scripts/lint.sh`, `./scripts/typecheck.sh`,
  `./scripts/format-check.sh`
- **Commit:** `test(s5.1): manual integration verification notes` (or no commit if nothing changed)

## Execution order

```
T1 (domain) ──▶ T2 (API) ──▶ T3 (types+client) ──▶ T4 (component+i18n) ──▶ T5 (page) ──▶ T6 (manual)
```

Strictly sequential — each task consumes the previous task's contract. Dependency graph is a chain,
therefore **acyclic**; no circular dependencies. No parallelism available within the story (a single
developer across one contract seam); the epic gets its parallelism at s5.3 ∥ s5.4.

**Risk-first justification:** T1 carries the only unknown (fixture ripple from a frozen-dataclass
change) and runs first. Everything after it is mechanical.
