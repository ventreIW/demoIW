## What to improve
- **Integration test for aggregate endpoint**: The initial approach tried to generate a scenario (which needs OpenRouter) and failed. Had to pivot to 404-only tests. The full data-composition path is tested by the unit-level repo tests but not by an integration-level E2E. A better approach would seed data via SQLAlchemy insert in the integration test, similar to the unit tests.
- **Test infrastructure**: The WSL environment had missing dependencies (httpx, aiosqlite, pydantic-settings) and a pydantic-core version mismatch that required a background pip install. This should be a one-time setup per environment.
- **Pre-existing test check**: The `test_repositories.py` test asserts exact sets of abstract methods — when adding a new method to the port, this test breaks. Caught it by running the full suite, but this is a brittle pattern.

## Heutagogical Checkpoint
1. **What did I learn?** The `rai pattern add` command stores patterns locally in the project's raise.db. The `rai signal query` command can confirm the implement-complete signal for the current HEAD. The `ICommunicationRepository` port + adapter pattern follows the exact same structure as the other repos — no surprises.

2. **What would I change about the process?** Write the integration test with direct SQLAlchemy seeding from the start rather than trying to go through the generate endpoint. This avoids the OpenRouter dependency and produces a more targeted test.

3. **Framework improvements?** The Jidoka orphaned test check in the implement skill is too aggressive — it flags any test importing from a modified module, even when the test is for a different interface in the same file. The check should be scoped: only flag tests that import from the *specific symbol* that was added/modified, not the entire module.

4. **More capable of now?** Experience with FastAPI read-model composition (aggregate endpoint over 5 repos), frontend dynamic route patterns with next-intl, and understanding of the communication entity lifecycle in the demoIW codebase.
