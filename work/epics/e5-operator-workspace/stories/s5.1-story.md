# Story: Operations Panel — Prioritized Case List

## User Story
As the **collections operator (P-01)**,
I want **a prioritized case list as my default workspace, one row per client showing the numbers I
act on**,
so that **I can see who to chase first without opening every account.**

## Acceptance Criteria

### Scenario: The panel lists the active scenario's prioritized cases
```gherkin
Given an active scenario with scored, prioritized clients
When the operator opens the operations panel
Then a case list renders one row per client
And each row shows client, outstanding amount, days overdue, score, and category
And rows are ordered by priority rank (most important first)
```

### Scenario: The panel is Spanish-first
```gherkin
Given the locale is "es"
When the operations panel renders
Then all labels and column headers come from next-intl messages (no hardcoded strings)
```

### Scenario: Empty / no active scenario
```gherkin
Given there is no active scenario (or it has no prioritized cases)
When the operator opens the operations panel
Then an empty-state message is shown, not an error or a blank table
```

### Scenario: Backend unavailable
```gherkin
Given the prioritized API returns an error
When the operations panel loads
Then a friendly error state is shown (not a crash), with the option to retry
```

## Examples (Specification by Example)
| State | Render |
|---|---|
| active scenario, 60 cases | table of 60 rows, rank-ordered; row 1 = highest priority |
| row data | `Comercializadora del Bajío · $12,480 · 47 días · 82.5 · Alta` |
| no active scenario | empty state: "No hay un escenario activo" (i18n key) |
| API 500 | error state with retry |

## Notes
- **Contract seam (design decision):** E4's `GET /scenarios/{id}/prioritized` returns `client_id,
  outstanding, score, rank, expected_recoverable, category` — **not** client *name* or *days_overdue*,
  both of which the row must show. s5.1 must resolve this: either extend `/prioritized` (and its
  response model) to include `name` + `days_overdue`, or compose them from another read. Decide in
  `/rai-story-design`; prefer the smallest honest change.
- Reuses the `lib/api` fetch pattern, next-intl, shadcn/ui table primitives, `MainLayout`.
- Out of this story: case **detail** (s5.2), recording contact results / actions (s5.3), comms (s5.4/5.5).
- Keep `es.json`/`en.json` key parity (E4 close verified 56/56 — do not regress).
