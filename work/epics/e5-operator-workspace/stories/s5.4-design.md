# S5.4 Design — Communications Generator Backend

## Overview

Backend for generating AI-assisted communication drafts. The operator selects a client in the case detail view, chooses a channel (email, phone, WhatsApp) and tone (formal, firm, urgent), and receives a generated draft. Every draft is persisted with audit metadata (timestamp, operator, model, prompt version).

## Scope (from E5 scope.md)

| Item | Description |
|---|---|
| **Endpoint** | `POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/communications` |
| **Input** | `channel: Channel`, `tone: Tone` (plus implicit `scenario_id`, `client_id` from path) |
| **Output** | Generated draft text + persisted `Communication` entity (status=`DRAFT`) |
| **LLM** | OpenRouter via `ILLMPort` using `settings.MODEL_COMMUNICATIONS` |
| **Prompt** | Config-driven template in `prompts/communications/v1_draft.txt` (mirrors `prompts/data_enrichment/`) |
| **Persistence** | `ICommunicationRepository.add()` → `CommunicationORM` |
| **Audit** | Every draft stored with: timestamp, operator (implicit via session), model, prompt version |

## Dependencies (already done)

- **S5.2** — Case detail endpoint provides client context (profile, invoices, payments, score, existing comms)
- **S3.2** — `OpenRouterAdapter` implements `ILLMPort`; config has `MODEL_COMMUNICATIONS`
- **E2** — `CommunicationORM`, `ICommunicationRepository`, `SQLAlchemyCommunicationRepository`, mappers

## Architecture

```
POST /api/v1/scenarios/{sid}/clients/{cid}/communications
        │
        ▼
GenerateCommunicationDraft (use case)
        │
        ├──► Fetch case aggregate (reuse S5.2 logic: client, invoices, payments, score, comms)
        ├──► Build prompt from template + case context
        ├──► Call ILLMPort.generate(prompt, model=MODEL_COMMUNICATIONS, max_tokens=512)
        ├──► Persist Communication(draft_text=response, channel, tone, status=DRAFT)
        └──► Return CommunicationSummaryResponse (draft_text, channel, tone, status, created_at)
```

### 5. Router Endpoint (`app/routers/cases.py`)

```python
class GenerateCommunicationRequest(BaseModel):
    channel: Channel
    tone: Tone

@router.post(
    "/{scenario_id}/clients/{client_id}/communications",
    response_model=CommunicationSummaryResponse,
    status_code=201,
)
async def generate_communication(
    scenario_id: UUID,
    client_id: UUID,
    body: GenerateCommunicationRequest,
    use_case: GenerateCommunicationDraft = Depends(get_generate_communication_draft_use_case),
) -> CommunicationSummaryResponse:
    response = await use_case.execute(
        GenerateCommunicationDraftRequest(
            scenario_id=scenario_id,
            client_id=client_id,
            channel=body.channel,
            tone=body.tone,
        )
    )
    return _communication_to_summary(response.communication)
```

## Data Flow

```
Request: POST /scenarios/{sid}/clients/{cid}/communications
  { "channel": "email", "tone": "formal" }

1. Validate scenario exists (404 if not)
2. Validate client exists & belongs to scenario (404 if not)
3. Fetch:
   - Client profile (name, sector_description, payment_pattern)
   - Invoices (folio, amount, due_date, days_overdue, status)
   - Payments (amount, date, method)
   - Score (value, category, explanation) — latest for this client in scenario
   - Existing communications (channel, tone, draft_text, status, created_at)
4. Build prompt with all context
5. Call OpenRouter (MODEL_COMMUNICATIONS, max_tokens=512)
6. Persist Communication:
   - id: uuid4()
   - client_id, scenario_id
   - channel, tone (from request)
   - draft_text: LLM response
   - status: DRAFT
   - created_at: now(UTC)
7. Return CommunicationSummaryResponse
```

## Error Handling

| Scenario | HTTP Status | Detail |
|---|---|---|
| Scenario not found | 404 | "Scenario not found" |
| Client not found | 404 | "Client not found" |
| Client not in scenario | 404 | "Client not found in scenario" |
| OpenRouter failure | 502 | "Communication generation failed" |
| Prompt template missing | 500 | "Prompt template not found" |


## Out of Scope (per E5)

- Real message delivery (email/SMS/WhatsApp) — "send" = status `SENT` + audit row only
- Frontend flow (S5.5) — editable draft, channel/tone selector, confirm-to-send
- Multi-operator auth — demo is single-operator
