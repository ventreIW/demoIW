# Retrospective: S5.1 — Operations Panel (Prioritized Case List)

**Dates:** 2026-07-27 (scope) → 2026-07-28 (implement + review)
**Estimated:** S (scope) / Moderate (design, after gemba) · **Actual:** 6 tasks, one session
**Tests:** backend 345 → 353 · frontend 49 → 70 · all gates green

## Summary

Delivered E5's walking skeleton: the operator can open `/cases` and see the active
scenario's prioritized queue — rank, client name, outstanding, days overdue, score, and a
localized category badge — with empty, error, and no-active-scenario states, in ES and EN.

The story was scoped as "render a list from an endpoint that already exists". It turned out
the endpoint could not express two of the five required columns, and two of its query
parameters had never worked. The list was the easy half.

## What went well

- **The gemba walk paid for itself before a line was written.** Reading
  `routers/scenarios.py` found `getattr(c, "days_overdue", 0)` against a dataclass with no
  such attribute — meaning `?days_overdue_min=30` returned an *empty* portfolio and
  `?sort=days_overdue` was a no-op. The column the UI needed and the field whose absence
  broke the filter were the same field, so fixing it was in scope rather than creep.

- **Risk-first task ordering worked exactly as intended.** T1 was sequenced first
  specifically because a frozen-dataclass change might ripple into seed-42 fixtures. It
  did — 6 failures across 3 files, surfaced on task one instead of after the frontend was
  built on top.

- **T6 justified its existence twice.** The manual integration test against running
  software caught two defects that all 424 passing tests could not: `category` serializes
  lowercase (`"high"`, not `"High"`), which would have rendered a blank badge in
  production; and `/cases` was unreachable behind a middleware guard reading a cookie
  nothing ever sets. Both would have shipped.

- **Fixed the bug honestly rather than the test.** The old `test_days_overdue_min_filter`
  could have been left passing. It now asserts a non-empty proper subset with exact
  membership, so silent-zero cannot return.

## What to improve

- **I wrote the type, the component, and the fixture in one sitting, so they agreed with
  each other and were all wrong.** `'High' | 'Medium' | 'Low'` was an assumption, never a
  verified fact, and the fixture I wrote to test it inherited the assumption. The backend
  enum was three lines away and I never opened it. Cheap fix, embarrassing cause: I
  verified the *field names* against the live payload during the gemba walk but not the
  *value domain* of the one field that is an enum.

- **My orphaned-test check produced a false positive** by interpolating a path containing
  `[locale]` into a `grep` pattern, where the brackets became a character class. It cost a
  round-trip to disprove. Worth `grep -F` in that check.

- **Two bugs of the same species in one endpoint suggests a third.** `days_overdue` and
  `category` were both dead filters hidden by vacuous assertions. Nobody swept the rest of
  the API for the same shape.

## Heutagogical Checkpoint

1. **What did I learn?** That "all tests pass" and "the feature works" are independent
   claims, and the gap between them is exactly the set of assumptions the tests and the
   code share. Concretely: `test_category_filter` asserts `case["category"] == "High"`
   inside a `for` loop over an empty list, then asserts `value_share >= threshold` — which
   passes because `value_share` comes from the *unfiltered* portfolio. Two assertions,
   both green, zero information. The test is not weak; it is *vacuous*, which is worse,
   because it occupies the space where a real test would go.

2. **What would I change about the process?** Capture a real payload from the running
   system *during design*, not during T6. My design document's example payload was
   handwritten from the domain classes — and it was wrong in exactly the way the code
   turned out to be wrong, because both came from the same reading. Ten seconds of `curl`
   at design time would have made the fixture correct from the start and made T6 a
   confirmation instead of a discovery.

3. **Framework improvements?** Two. (a) The implement skill's orphaned-test check should
   use `grep -F` for paths — Next.js `[locale]` directories break it. (b) `rai gate check
   gate-tests --scope` resolves paths relative to `backend/`, not the repo root, and
   accepts only a single path; both cost a round-trip to discover and are worth stating in
   the gate policy. Also: `rai gate check --all` hangs past 120s in this project, and
   `rai artifact emit` does not exist in CLI v3.0.0 despite the design skill's Output
   section requiring it — the Markdown fallback is what every story has actually used.

4. **More capable of now?** I can recognise the vacuous-assertion shape on sight —
   iteration over a possibly-empty result, or an assertion computed from a different
   object than the one under test. And I now treat enum *values* as facts to verify from
   the source of truth, not to infer from the enum's Python member names.

## Improvements applied

- Filter test rewritten to assert a non-empty proper subset with exact membership.
- Category test now enumerates all three real enum values so a casing regression fails.
- Peso formatting maps `es → es-MX`: bare `es` is Spain and renders `184.321 MXN`, the
  wrong separator convention for a Mexican receivables book (`$184,321`).
- Four findings filed to `dev/parking-lot.md` rather than silently fixed or forgotten.

## Patterns added / reinforced

**Added:**
- *(technical)* Filter/sort tests asserting only status 200 — or iterating a result list
  without asserting non-emptiness — prove nothing. Assert the subset relationship.
- *(process)* A fixture, a type, and a component written together can share one wrong
  assumption and all agree. Pin fixtures to payloads captured from the running system.
- *(codebase)* A route guard reading state nothing writes stays invisible until the second
  route is added.

**Reinforced:** `BASE-016` (+1, Pydantic response models mirroring domain),
`BASE-029` (+1 — quality review catching type lies and test muda is precisely what
happened here). `BASE-053` and `PAT-R-3` voted 0 (not relevant to this story).
