# S5.3 Scope — Contact Result + Status Update (→ Rescore)

**Status:** Active | **Size:** S | **Owner:** Nano | **Branch:** `story/s5.3/contact-result-rescore`

## In Scope
- `IContactResultRepository` port (`app/ports/repositories.py`)
- `SQLAlchemyContactResultRepository` adapter (`app/adapters/persistence/sqlalchemy_contact_result_repo.py`)
- `RecordContactResult` use case (`app/application/use_cases/record_contact_result.py`): persist ContactResult → update client status → call `RescoreScenario.execute` → return updated portfolio
- `POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/contact-result` endpoint (`app/routers/cases.py` or new router)
- Container provider `get_record_contact_result_use_case` wiring contact_result_repo + client_repo + scenario_repo + rescore_use_case
- Tests: persist contact result, call rescore, return portfolio; invalid contact_result_type → 422; missing client → 404
- Reuse `RescoreScenario` (E4 s4.6) and `ContactResultType` enum — no new scoring logic

## Out of Scope
- Changing the rescore algorithm (E4 s4.6 owns it)
- UI for recording contact (frontend owns it; backend provides endpoint)
- Communications draft/send (s5.4/s5.5)
- Multi-operator auth / roles (demo is single-operator)

- [ ] ContactResultType validation: invalid type → 422
- [ ] Missing client/scenario → 404
- [ ] Rescore is triggered and score adjustment applied per `_CONTACT_RESULT_DELTA`
- [ ] Container exposes use case; all new tests pass; ruff/format/mypy clean on touched files
