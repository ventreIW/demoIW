# S5.3 Scope — Contact Result Form (Frontend)

**Status:** Active | **Size:** S | **Owner:** Renor | **Branch:** `story/s5.3/contact-result-form-frontend`

## In Scope
- ContactResultForm component: dropdown with ContactResultType options, notes textarea, Record button
- API client function (`POST /api/v1/scenarios/{scenario_id}/clients/{client_id}/contact-result`) in `lib/api/cases.ts`
- Integration into CaseDetail page: form rendered in a new section, calls API on submit
- Optimistic score update: after successful record, update the displayed score from the response portfolio
- Loading state: disabled button + spinner while request is in flight
- Error handling: display validation errors (422) and server errors inline
- Tests: Vitest unit tests for the form component (mock API, verify render/submit/error states)
- i18n keys: `es.json` / `en.json` for form labels, options, status messages

## Out of Scope
- Backend endpoint (already done by Nano — merged to main)
- Change to the rescore algorithm (E4 s4.6 owns it)
- Communications draft/send (s5.4/s5.5)
- Multi-operator auth / roles (demo is single-operator)
- Persisted contact history list on the case detail (future enhancement)
