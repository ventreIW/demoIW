# S5.5 — Communications Generator Frontend Flow

**Epic:** E5 Operator Workspace
**Story:** s5.5
**Size:** S
**Status:** draft
**Depends on:** s5.4
**Owner:** Renor
**Branch:** story/s5.5/communications-generator-frontend

## User Story
As a collections operator viewing a case detail,
I want to generate, edit, and send an AI-assisted communication draft for the client,
so that I can handle the full communications workflow from the case detail view.

## Acceptance Criteria

### Scenario: Generate a draft from case detail
```gherkin
Given I am viewing the case detail for a client
When I select channel "email" and tone "formal"
And I click "Generate draft"
Then the system calls POST /api/v1/scenarios/{sid}/clients/{cid}/communications with {channel: "email", tone: "formal"}
And the generated draft text appears in an editable text area
And the channel and tone badges are shown on the draft
```

### Scenario: Edit draft before sending
```gherkin
Given a generated draft is displayed in the editable area
When I modify the draft text
Then the text area reflects my changes
And the "Send" button becomes enabled
```

### Scenario: Confirm and send draft
```gherkin
Given a draft has been generated and reviewed
When I click "Send"
Then a confirmation dialog is shown
When I confirm
Then the draft is sent (status transitions draft → sent)
And success feedback is displayed
And I am returned to the case detail view
```

### Scenario: Cancel send
```gherkin
Given a confirmation dialog is shown
When I cancel
Then the draft remains editable
And no status transition occurs
```

### Scenario: API error on generate
```gherkin
Given the communication backend is unavailable
When I click "Generate draft"
Then an error message is displayed inline
And I can retry generation
```

### Scenario: Send endpoint unavailable
```gherkin
Given I have confirmed sending a draft
And the send API returns an error
Then an error message is displayed
And the draft remains in "draft" status
```

## Examples (Specification by Example)

| Input | Action | Expected Output |
|-------|--------|-----------------|
| channel=email, tone=formal | Generate draft | Editable text area with draft, channel/tone badges |
| Modify draft text | Edit text area | Updated text in area, Send button enabled |
| Click Send | Confirm in dialog | Status transitions to "sent", success toast |
| Click Send | Cancel dialog | Draft remains editable, no transition |
| Backend 502 | Generate draft | Error message shown inline, retry available |

## Notes

- Consumes s5.4 backend endpoint `POST /api/v1/scenarios/{sid}/clients/{cid}/communications` for draft generation
- The "send" action transitions draft → sent (status update); no real external transport
- Requires a `PATCH /api/v1/scenarios/{sid}/clients/{cid}/communications/{comm_id}/send` endpoint (or equivalent) on the backend — verify availability during design
- I18n keys in `es.json` / `en.json` for all new UI strings (comms labels, tones, channels, buttons, status)
- Launched from the case detail page (RF-05.5) — add a "Communications" section with a Generate button
