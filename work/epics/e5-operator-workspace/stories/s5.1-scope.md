# s5.1 Scope — Operations Panel (Prioritized Case List)

Status: **Active** — started 2026-07-27. Branch: `story/s5.1/operations-panel-case-list`. Size: S.
First story of E5; walking-skeleton foundation (consumes E4 `/prioritized`).

## In Scope
- Frontend operations-panel page (e.g. `[locale]/cases`) rendering the active scenario's prioritized
  case list — one row per client: client, outstanding amount, days overdue, score, category; rank-ordered.
- `lib/api` client method for `GET /scenarios/{id}/prioritized` (+ resolving the active scenario).
- Loading, empty, and error states.
- ES-first via next-intl; new message keys added to **both** `es.json` and `en.json` (parity kept).
- **Minimal backend contract fix** if design chooses it: add `name` + `days_overdue` to the
  prioritized case response so the row can show them (the response currently omits both). Smallest
  honest change; response model mirrors domain.
- Tests: component render (rows + fields), empty/error states, i18n (no hardcoded strings), and — if
  the API is extended — a backend test for the new fields.

## Out of Scope
- Case detail view (s5.2), contact-result/status actions (s5.3), communications (s5.4/s5.5).
- Sorting/filtering UI controls (the API supports them; UI controls are a later polish — parking lot).
- Pagination (demo scenarios are ~hundreds of rows; render all).
- Making the prioritized endpoint read persisted scores (parked E4 follow-up).

## Done when
- [ ] The operations panel renders the active scenario's prioritized cases, rank-ordered, one row per client.
- [ ] Each row shows client, outstanding amount, days overdue, score, category.
- [ ] Empty and error states render (no crash, no blank table).
- [ ] All labels via next-intl; `es.json`/`en.json` key sets identical.
- [ ] vitest green; `tsc`, eslint, prettier clean; if backend extended, pytest + mypy + ruff green.
- [ ] Contract seam resolved: `name` + `days_overdue` available to the row (documented in design).
