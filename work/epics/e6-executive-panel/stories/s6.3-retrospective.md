## Summary

A Spanish question now becomes a validated `QueryIntent`, executes against the same `PortfolioKpis`
aggregate the dashboard renders, and returns numbers, Spanish prose and a citation. The LLM never
emits SQL and no string it returns reaches the database.

The security property is **structural rather than procedural**: `execute()` accepts a `QueryIntent`,
and a `QueryIntent` cannot hold a string that is not an enum member. There is no allow-list *check*
anyone can forget to call, because the field types are the allow-list.

## What to improve

- **The first live call should have come earlier.** T6 is correctly last for *merge safety*, but a
  single throwaway call at T4 — just to look at what the model actually emits — would have caught
  the reasoning-model output shape before it was baked into a prompt, a use case and two test files.
  Cost of moving it: one request. Cost of not: a prompt rewrite, a new extraction function, four
  regression tests and two fixture updates.
- **I committed T3 with a live type error.** The verification chain was

## The defect no stub could find

The configured model is a **reasoning** model. Its first live narration returned the entire chain of
thought:

> *"We need to produce a brief explanation in Spanish, max 3 sentences… Let's craft: "El portafolio
> Scenario-retail presenta…". That's two sentences. Good. Check rules: mention portfolio"*

— with the real sentence buried in the middle. **All 541 tests passed**, because a stub returns
whatever prose it is handed. Everything the tests were built to check (intent, figures, citation,
agreement with `/kpis`) was correct; the one thing a director would actually read was unusable.

**Fix:** the narrate prompt now requires a `RESPUESTA:` marker and the use case takes only what
follows it (`rsplit`, so a model echoing the prompt's own example doesn't win). An unmarked reply
degrades to `narrative=None` rather than showing the director a model talking to itself — the
figures are the deliverable and a chart without prose beats prose without sense. Four regression
tests lock it; re-verified live.

**The general lesson: instructing a model and verifying it complied are different things.** Where
output shape matters, make compliance checkable — a delimiter the code can find beats a rule the
prompt merely states.

## Heutagogical Checkpoint

1. **What did I learn?** That a stubbed test suite has a specific blind spot with a hard edge: it
   can prove every *contract* — status codes, field presence, figure provenance, degradation
   behaviour — and still say nothing about whether the model's output is *usable*. My 541 tests were
   not weak; they were complete over the wrong axis. Also, concretely: `rai gate check` run from the
   wrong directory prints an error and **exits 0**, which is why s6.2's plan shipped unrunnable
   commands, and demoIW's `lint.sh`/`format-check.sh` use `set -e` with the frontend first, so a red
   frontend means the backend half never runs at all.
2. **What would I change about the process?** Spend one live call the moment an LLM path first
   returns a string end-to-end — not as verification, just to *look at it*. The plan treats live
   verification as a final gate; it should also be a T4 sanity glance. And never pipe a gate to
   `tail` inside an `&&` chain: check the exit code you actually mean.
3. **Framework improvements?** Three, filed: (a) `rai gate check` exiting 0 on a missing manifest is
   a silent-success bug and the highest-value fix here — a gate that cannot fail loudly is worse
   than no gate; (b) `rai artifact emit` still absent in CLI v3.0.0, so the design was written as
   Markdown like every story before it; (c) `rai graph query` still fails with
   `no such column: data_json`, so PRIME's retrieval half returned nothing across all four phases of
   this story while `rai pattern add` accepted four more patterns — the store is now write-only
   across three consecutive epics.
4. **What am I more capable of now?** Building an LLM feature whose safety does not depend on
   anyone remembering to validate: constrain the model's output to a type whose fields are enums,
   and the check cannot be skipped because there is no check. And budgeting a free-tier quota as a
   real design constraint — 13 of 50 requests, zero from the suite, the 409 proven to precede any
   call by a stub that raises rather than a count asserted afterwards.

## Open acceptance item (carried, stated — not silently passed)

**Real-Postgres end-to-end remains unverified.** The live run used **SQLite in-memory** via the ASGI
transport; the backend is otherwise Postgres-only and this host has neither Postgres nor Docker.

What that *does* cover: the full HTTP path, the real `OpenRouterAdapter`, real model output,
translation, execution, narration, citation, and agreement with `/kpis` — verified in one process.
What it does **not** cover: Postgres-specific behaviour (asyncpg driver, the Postgres-only Alembic
migrations, real connection pooling under load).

This is the same gate E4 deferred, E5 closed open, and s6.2 carried. **Fourth consecutive story.**
It is E6's M4 line item and should not be treated as satisfiable by accumulation.
