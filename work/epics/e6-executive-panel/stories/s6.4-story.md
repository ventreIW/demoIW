# Story: NL query — frontend (question input, result chart, narrative, citation)

## User Story

As a **collections director (P-02)**,
I want to **type a plain-language question in Spanish about the active portfolio and see the answer as a chart with a narrative and a citation**,
so that **I can interrogate the book directly from the executive page without waiting for a report** (RF-06.3, RF-06.4).

## Acceptance Criteria

### Scenario: A supported question renders a result
```gherkin
Given the executive page shows a scored active scenario
When I type "¿Cuánto está vencido por categoría de score?" and submit
Then the API POST /api/v1/scenarios/{id}/query is called with that question
And the response is answerable=true
And the result series renders as a chart reusing the s6.2 chart styling
And the Spanish narrative is shown beneath the chart
And the scenario is cited by name and id
```

### Scenario: A successful answer without a narrative still renders the chart
```gherkin
Given the API returns answerable=true with narrative=null (a designed state)
When I submit a question
Then the chart renders from the result series
And no narrative paragraph is shown (no placeholder, no error)
```

### Scenario: An out-of-vocabulary question shows the supported examples
```gherkin
Given the API returns 200 with answerable=false and a "supported" vocabulary object
When I submit an unsupported question
Then an honest "cannot answer" message is shown using the returned reason and message
And example questions are rendered from the API's supported vocabulary (metrics × dimensions)
And no fabricated number and no raw query are displayed
```

### Scenario: Translation unavailable degrades without breaking the dashboard
```gherkin
Given the API returns answerable=false with reason="translation_unavailable"
When I submit a question
Then the "cannot answer" message names translation unavailability
And the KPI dashboard above continues to render normally
```

### Scenario: An unscored scenario is refused before any request
```gherkin
Given the scenario has NOT been scored (409 from the API)
When I submit a question
Then the existing PortfolioNotScoredError path shows the actionable "score this scenario" state
And no chart or fabricated figure is shown
```

## Examples (Specification by Example)

| Question (ES) | API response | Expected UI |
|---|---|---|
| "¿Cuánto está vencido por categoría de score?" | answerable=true, series `[{high,…},{medium,…},{low,…}]`, narrative, scenario citation | Chart + narrative + citation |
| (any) | answerable=true, narrative=null | Chart only, no narrative paragraph |
| "¿Qué clientes pagaron tarde en marzo?" | answerable=false, reason=out_of_vocabulary, message, supported | "Cannot answer" + example questions from supported vocabulary |
| (any) | answerable=false, reason=translation_unavailable | "Cannot answer" naming unavailability; dashboard intact |
| (unscored scenario) | 409 | Existing "Score this scenario" empty state |

## Notes

**Governed by [ADR-008](../../../dev/decisions/adr-008-nl-query-constrained-intent.md).** The
frontend consumes, never hardcodes. The `supported` vocabulary and example questions come from the
s6.3 API response, so the UI cannot drift from the backend vocabulary (see E6 pull-board s6.4 note).

**Contract source of truth:** the s6.3 response shape (design.md §Examples and the backend
`QueryResponse`/`CannotAnswerResponse` schemas). Frontend types should be written against the real
payload, mirroring the s6.2 instruction to derive from `s6.1-payload.json` — fetch and capture a
real `query` payload if feasible, else type from design.md examples. **No hardcoded question list.**

**Three distinct user-facing states** (from s6.3 design D6):
- `answerable=false` → show the returned reason/message + supported vocabulary examples
- 409 → existing `PortfolioNotScoredError` "score this scenario" path
- 502 / other → "try again" degradation; dashboard unaffected

**Reuse:** s6.2's `SegmentationChart` styling/hand-rolled CSS for the result chart. The query
`result.series` is `{label, value}` (not `SegmentBucket`), so a chart variant or a small adapter is
likely; add a typed shape rather than mutating the KPI type.

**ES-first:** all copy keys (question placeholder, submit, "cannot answer", example-question label)
must exist in `es.json` with `en.json` parity.
