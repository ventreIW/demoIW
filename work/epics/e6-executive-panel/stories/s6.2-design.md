# S6.2 Design — Executive Dashboard (Frontend)

**Epic:** E6 · **Size:** M · **Complexity:** moderate (7 components, 0 external integrations, hand-rolled SVG charts)

---

## Problem

The finance director (P-02) has no portfolio-level view. E4/E5 produced intelligence for one collector at a time; there is no dashboard showing what the book is worth, where value concentrates, or how recovery is trending.

## Value

First surface that shows the *portfolio* — the view that justifies the system to the person who funds it. Enables RF-06.1 (KPI cards) and RF-06.2 (segmentation charts) with ES-first copy and visible staleness (`scored_at`).

---

## Approach

Create a new `/[locale]/executive` page as a server component that fetches KPIs from `GET /api/v1/scenarios/{id}/kpis`. Build KPI cards and three hand-rolled SVG/CSS segmentation charts (days-overdue buckets, amount ranges, score categories). Add API client typed from `s6.1-payload.json`. Update sidebar executive link from `#` to the new route. Add ES/EN i18n keys with full parity. All components use Vitest mocks — no backend dependency for tests.

---

## Design Decisions

| ID | Decision | Rationale |
|----|----------|-----------|
| **D1** | Server component for data fetching, client component for charts | Next.js app router pattern: `page.tsx` (server) fetches data, passes to `ExecutiveDashboard` (client) which composes interactive SVG charts. Matches existing patterns in `cases/page.tsx` and `scenarios/page.tsx`. |
| **D2** | Types derived from `s6.1-payload.json`, not hand-written | s5.1 shipped a defect because every layer inherited one assumption read from domain classes. The captured s6.1 payload is the contract — TypeScript types must mirror it exactly. Prevents silent contract drift. |
| **D3** | Hand-rolled SVG/CSS charts — no charting library | Per E6 scope §Architecture decisions: charting is not an ADR; design.md §Charting specifies hand-rolled SVG/CSS. Keeps bundle size minimal and avoids supply chain risk. Three simple bar charts need ~100 LOC total. |
| **D4** | 409 unscored scenario → actionable empty state with "Score this scenario" CTA | ADR-009: zeros are a failure mode. An unscored scenario must show an actionable empty state, not a dashboard of zeros. The CTA navigates to the scoring page (existing `/scenarios` or a new score endpoint). |
| **D5** | `scored_at` visible on every dashboard view | ADR-009 §Alternatives: surface `scored_at` in the UI. Visible staleness over silent inconsistency. Director can judge if dashboard reflects current scores. |
| **D6** | Sidebar executive link uses dynamic locale from `usePathname` | `MainLayout` is a client component (uses `useTranslations`). Can use `next-intl/navigation`'s `usePathname` to construct the correct localized href. Ensures ES/EN routing works correctly. |

## Examples

### KPI API client usage

```typescript
import { fetchKpis } from '@/lib/api/executive'
import type { PortfolioKpis } from '@/types/executive'

const kpis: PortfolioKpis = await fetchKpis(scenarioId)
// kpis.total_outstanding, kpis.segmentation.days_overdue_bucket, etc.
```

API client mirrors existing patterns in `scenarios.ts` and `prioritized.ts`. Returns typed `PortfolioKpis` or throws on 404/409.

### Executive page server component

```tsx
import { getTranslations } from 'next-intl/server'
import { cookies } from 'next/headers'
import MainLayout from '@/components/layout/MainLayout'
import ExecutiveDashboard from '@/components/executive/ExecutiveDashboard'
import { fetchKpis } from '@/lib/api/executive'

export default async function ExecutivePage() {
  const t = await getTranslations('executivePage')
  const cookieStore = await cookies()
  const activeId = cookieStore.get('active_scenario_id')?.value
  
  let kpis: PortfolioKpis | null = null
  let error: string | null = null
  let isUnscored = false
  
  if (activeId) {
    try {
      kpis = await fetchKpis(activeId)
    } catch (e) {
      if (e instanceof Error && e.message.includes('409')) {
        isUnscored = true
      } else {
        error = e instanceof Error ? e.message : t('errorLoading')
      }
    }
  }
  
  return (
    <MainLayout>
      <div className="space-y-6">
        <h1 className="text-2xl font-bold text-slate-900">{t('title')}</h1>
        {error ? <ErrorMessage>{error}</ErrorMessage> :
         isUnscored ? <UnscoredState /> :
         kpis ? <ExecutiveDashboard kpis={kpis} /> :
         <NoActiveScenario />}
      </div>
    </MainLayout>
  )
}
```

Server component pattern matching `cases/page.tsx`. Fetches KPIs, handles 409 as unscored state, passes data to client component.

### SegmentationChart SVG example

```tsx
function SegmentationChart({ buckets, maxValue, t }: { buckets: SegmentBucket[]; maxValue: number; t: any }) {
  return (
    <div className="space-y-3">
      {buckets.map((bucket) => (
        <div key={bucket.label} className="space-y-1">
          <div className="flex justify-between text-sm">
            <span>{bucket.label}</span>
            <span className="font-medium">{bucket.client_count} clientes · {formatCurrency(bucket.outstanding)}</span>
          </div>
          <div className="h-4 bg-slate-100 rounded overflow-hidden relative">
            <div 
              className="h-full bg-slate-600 transition-all"
              style={{ width: `${(bucket.outstanding / maxValue) * 100}%` }}
            />
            <span className="absolute inset-0 flex items-center justify-end pr-2 text-xs text-white font-medium">
              {formatCurrency(bucket.expected_recoverable)} rec.
            </span>
          </div>
        </div>
      ))}
    </div>
  )
}
```

Hand-rolled horizontal bar chart. Bar width proportional to outstanding/maxValue. Shows client count, outstanding, and expected recoverable. No external dependencies.

## Acceptance Criteria

| ID | Description | Severity |
|----|-------------|----------|
| **AC1** | Dashboard shows four KPI cards: total overdue, expected recoverable, cases by category (high/medium/low), recovery rate (actual and expected) | MUST |
| **AC2** | Three segmentation charts render: days-overdue buckets (0-30, 31-60, 61-90, 90+), amount ranges (quartile labels), score categories (high/medium/low) | MUST |
| **AC3** | `scored_at` timestamp is visible on the dashboard for scored scenarios | MUST |
| **AC4** | Unscored scenario (409 response) shows actionable empty state with "Score this scenario" link/button that navigates to scoring | MUST |
| **AC5** | Sidebar executive link navigates to `/[locale]/executive` (not `#`) and works for both ES and EN locales | MUST |
| **AC6** | All executive dashboard copy keys exist in both `es.json` and `en.json` with parity | MUST |
| **AC7** | `vitest` green; no TypeScript errors | MUST |
| **AC8** | Dashboard renders within NFR-02 budget at 500 clients / 2,000 invoices | SHOULD |

## Drift Risks

| Risk | Description | Mitigation |
|------|-------------|------------|
| **AG2 (clone amplification)** | Risk of duplicating formatting logic (currency, numbers) that exists in cases/components. | Audit existing formatting in `CaseTable` and `ScenarioCard` before writing new formatters. Extract shared currency/number formatting to `lib/utils` if not already there. |
| **AG4 (fan-out >3 modules)** | New executive module touches page, API client, types, 3 components, layout, i18n — 7+ files. Moderate fan-out but each file has single responsibility. | Keep components pure and composable. `ExecutiveDashboard` composes `KpiCard` + `SegmentationChart`; page only fetches and routes. No cross-component state. |
