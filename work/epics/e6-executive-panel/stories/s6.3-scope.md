## Done when

- [ ] A supported Spanish question returns a validated `QueryIntent`, a result series, a Spanish
      narrative, and a citation naming the active scenario by name and id (RF-06.3, RF-06.4)
- [ ] The result series is computed from the **same** `PortfolioKpis` aggregate the dashboard
      renders — asserted by a test that builds both from one fixture and compares (ADR-008)
- [ ] Every narrative figure traces to the result series; a test asserts the narrator receives
      numbers only and never the database or the raw question's claims
- [ ] An untranslatable question returns `answerable=false` with the supported vocabulary listed —
      never a fabricated figure, never a raw query (ADR-008 degradation clause)
- [ ] `ExternalServiceError` from the adapter (rate limit / timeout / malformed body) degrades to
      the same structured refusal, and `GET /{id}/kpis` is proven unaffected in the same test
- [ ] An unscored scenario returns 409 naming `POST /{id}/score` **before** any LLM call is issued —
      asserted by a stub that fails the test if called
- [ ] The executor is **total** over `Metric` × `Dimension`: a parametrized test covers every
      combination, each either producing numbers or raising a typed rejection. No `else: pass`
- [ ] No model-supplied string is ever used as a field name, key, or query fragment — asserted by a
      prompt-injection test case
- [ ] `score_category` filter literals are built from `ScoreCategory` members; a test asserts
      `"high"` matches and `"High"` is rejected at validation rather than silently matching nothing
- [ ] Bucket sums hold: per-dimension `client_count` sums to the aggregate's `client_count`
      (the totality property s6.1 established, re-asserted through the query path)
- [ ] Full `pytest` green; `ruff format --check` and `ruff check` clean; OpenAPI schema valid
- [ ] Live verification run performed with a real model, translation hit rate over the fixture
      question set recorded honestly in the retrospective — including failures
- [ ] Retrospective written; `pull-board.md` and `scope.md` updated **in the same story**, not after
- [ ] Merged to `main` with `--no-ff` so the story boundary survives in history (s6.2 lesson)

## Open decisions carried into design

1. **`avg_days_overdue`** — extend `SegmentBucket` to carry it, or ship a three-metric vocabulary
   and correct ADR-008? Days-overdue survives s6.1's aggregation only as a bucket label.
2. **Filtering on `amount_range`** — labels are per-scenario quartile strings (`"$0 – $2,812"`),
   so there is no closed literal set. Restrict filters to closed-vocabulary dimensions, or address
   quartiles by ordinal?
3. **Live-call budget** — how many of the 50/day are spent on verification, and does the story
   close if the hit rate is poor but the failure is honest? (ADR-008 argues wrong ≠ unsafe.)
