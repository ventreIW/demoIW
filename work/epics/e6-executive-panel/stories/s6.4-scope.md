# S6.4: NL Query — Frontend scope

## In Scope
- Question input + submit on the executive page (`/[locale]/executive`)
- API client for `POST /api/v1/scenarios/{id}/query`
- Result chart for `answerable=true`, reusing s6.2's chart styling (hand-rolled CSS — no new charting dependency)
- Narrative paragraph shown when present; **absent (null) narrative renders the chart without the paragraph** (designed state per pull-board)
- Scenario citation display (name + id) via the s6.3 `scenario` field
- `answerable=false` handling: render the returned `reason`/`message` honestly + render example questions from the API's `supported` vocabulary (metrics × dimensions) — **never a hardcoded question list**
- 409 (unscored) → existing `PortfolioNotScoredError` "score this scenario" state; ensure no chart/fabricated figure
- Translation-failure degradation: "cannot answer", dashboard above stays intact
- Frontend types for the query request/response derived from the real s6.3 contract (not hand-written drift)
- i18n keys for ES/EN parity in `es.json` / `en.json`
- Vitest tests with mocked API responses (no backend dependency)

## Out of Scope
- Backend NL query API (s6.3 — done, merged to `main`)
- Any model/SQL invitation or free-string query construction (ADR-008 — structural, backend-side)
- Multi-turn / follow-up questions, saved queries, history (parking lot)
- English translation pass, PWA, accessibility audit (E7)
- Real-Postgres E2E verification (standing environment blocker, E7)
- Changing s6.2 `PortfolioKpis` / `SegmentBucket` / `/kpis` shapes

## Done when
- User can type a Spanish question and see a chart + narrative + citation for `answerable=true`
- A null narrative still renders the chart (no placeholder/error)
- Unsupported question shows an honest "cannot answer" with example questions from the API's `supported` vocabulary — no fabricated number, no raw query, no hardcoded list
- `reason=translation_unavailable` degrades gracefully; KPI dashboard remains intact
- Unscored scenario (409) reuses the existing actionable empty state
- ES/EN i18n key parity holds
- `vitest` green; no TypeScript errors; OpenAPI schema valid
- Story retrospective written
