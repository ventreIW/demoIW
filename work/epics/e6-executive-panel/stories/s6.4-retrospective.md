# Retrospective: S6.4 — NL Query Frontend

**Dates:** 2026-08-11 → 2026-08-11
**Estimated:** S (3 SP), simple
**Actual:** 4 plan tasks, 8 story commits, same day.

## Summary

Built the frontend half of RF-06.3/RF-06.4: a natural-language query panel on the executive
page that POSTs a Spanish question to the s6.3 `/query` endpoint and renders one of three
outcomes — an `answerable=true` result (chart + optional narrative + scenario citation), an
`answerable=false` honest refusal with example questions derived from the API's `supported`
vocabulary, or an error/retry state. 151/151 frontend tests green, tsc/lint/format clean, no
orphaned tests. The work reused s6.2's executive page and chart idiom with no new dependency.

## What went well

- **Contract-first, typed against real code.** `nlQuery.ts` and `askQuestion` were written from
  the actual `NlQueryResponse`/`RefusalReason`/`SUPPORTED_VOCABULARY` shapes read in
  `routers/executive.py`, `answer_nl_query.py`, and `query_intent.py` — not guessed. No drift at
  the type boundary.
- **No hardcoded question list.** The refusal state renders examples from `response.supported`,
  exactly as the E6 pull-board instructed, so the UI cannot drift from the backend vocabulary.
- **Null narrative handled as designed state** — the chart renders without a paragraph, no
  placeholder/error (AC3), which the pull-board flagged as the subtle case.
- **TDD held through all three code tasks** (RED test → GREEN component → REFACTOR), and the
  full frontend suite was run at close, not just scoped files.
- **WSL pitfalls navigated**: vitest run in background with generous timeouts, `tsc` via the
  direct path, eslint/prettier scoped to story files.

## What to improve

- **Vitest module-mock lesson (cost the most time).** `NlQueryPanel` imports
  `PortfolioNotScoredError` and does `e instanceof PortfolioNotScoredError`. My `vi.mock`
  factory only exported `askQuestion`, so the `instanceof` threw at runtime and the error-state
  test failed in a confusing way. Fixing the mock to export the error classes (mirroring
  `page.test.tsx`) resolved it. Persisted as PAT-R-15 — a future me won't rediscover it.
- **Currency-symbol assertion brittleness.** The first `QueryResultChart` test asserted exact
  `$655,498`; the jsdom runtime rendered `MX$655,498` (ICU data differs from standalone node),
  while the sibling `SegmentationChart` test asserts `$`. Switched to `container.textContent`
  numeric matching — the pattern SegmentationChart already uses for symbol-ambiguous values.
  Small, but a reminder to prefer symbol-independent assertions for currency.
- **Plan granularity for i18n.** The plan put all i18n keys in Task 3, but Task 2's chart needed
  `query.total`/`query.noData`. I committed the full query namespace with Task 2 — a harmless,
  correctly-flagged deviation, but the plan could have noted the chart's i18n dependency.

## Heutagogical Checkpoint

1. **What did I learn?** Writing the frontend half of a backend/frontend narrative split is
   fastest when the sibling story's design doc and committed payloads are the source of truth —
   I read s6.3's `design.md`, `routers/executive.py`, and `query_intent.py` before writing the
   story and the types, so the ACs and TypeScript contract matched the real API on the first
   pass. Also learned the concrete failure mode of an incomplete `vi.mock` factory.
2. **What would I change about the process?** In the vitest module-mock test, the `.mock` the
   component actually uses can be factored so both the page test and the panel test share one
   realistic factory (page's already exports the error classes; panel's now does too). Duplicating
   factory definitions across two test files is a small AG2 smell worth extracting.
3. **Framework improvements?** A reviewer/implementer tip would help: when a component does an
   `instanceof` on an imported class, the plan story could call out "your `vi.mock` must export
   that class." The skill's vitest-patterns reference already documents `useRouter`/`getByText`
   quirks; this is the same genus. The learning-record directories didn't exist for this story
   (no per-skill records), so the "learning chain" section is N/A this round.
4. **What am I more capable of now?** I can execute a full frontend story end-to-end under the
   RaiSE workflow (start → design → plan → implement → review) with correct AC typing, TDD, and
   WSL-aware gates, and I can finish the what-went-well loop by persisting the hard-won vitest
   mock lesson as a reusable pattern.
