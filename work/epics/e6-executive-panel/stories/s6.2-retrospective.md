## Summary

s6.2 built the executive dashboard frontend against the KPI aggregate from s6.1: four KPI cards,
three hand-rolled CSS segmentation charts, a visible `scored_at` timestamp, and an actionable
empty state for the 409-unscored case. The dead `sidebar.executive` link (`#`) was wired to the
localized `/{locale}/executive` route. All in ES and EN.

The story followed the discipline the epic asked for: the TypeScript types were built from
`s6.1-payload.json` — a real curl-captured response — rather than from the domain classes. That is
the specific precaution E6's design called out, because it is exactly how s5.1 shipped `'High'`
against an API that returns `'high'`, a bug still open in this repo.

## What went well

- **Typed against the real payload, not the domain model.** The single most important instruction
  carried into this story from s5.1's failure, and it was followed. No enum-case seam bug shipped.
- **State branching placed at the right layer.** The server page owns the error / 409-unscored /
  no-active-scenario branches; the client dashboard composes given KPIs. This matches `design.md`
  D1 and the existing `cases/page.tsx` convention, so it reads like the surrounding code.
- **ADR-009 honored in the UI, not just the API.** An unscored scenario renders an actionable
  "score this scenario" CTA — not a dashboard of zeros. The API's refusal to fabricate zeros would
  have been pointless if the frontend had rendered them anyway.
- **No new charting dependency.** Hand-rolled CSS bars per E6 scope D3, keeping the demo's
  dependency surface flat.
- **Locale/region mapping reused rather than reinvented** (`es→es-MX`, `en→en-US`), avoiding the
  ES/EN currency and date formatting drift flagged as AG2.
- **Honest blocker reporting.** The session did not claim an E2E it could not run.

## What to improve

- **The story stopped at code-complete but was recorded as finished.** Its commits went to `main`
  and work moved on, but no retrospective existed for four days, and `pull-board.md` and
  `scope.md` still read `s6.2 | backlog` on 2026-08-11. The tracker was the last thing anyone
  would trust and the first thing that went stale.
- **The branch was merged without `--no-ff`.** `story/s6.2/kpi-dashboard-segmentation` existed and
  was used correctly, but its commits landed on `main` fast-forwarded, so `git log --merges` shows
  no trace of the story — unlike s5.4, s5.5 and s6.1, which all left merge commits. The branch
  boundary is unrecoverable from history now.
- **Live E2E deferred for the third consecutive epic.** See open acceptance item below.
- **Gate tooling could not target the frontend.** `rai gate check gate-tests --scope frontend/...`
  resolves paths relative to `backend/`, so the plan's own per-task verification commands were
  unrunnable as written; the session fell back to `npx vitest run`. The plan should not have
  specified commands that cannot execute.

## Open acceptance item (carried, not closed)

**AC3 — "Dashboard renders within NFR-02 budget at 500 clients / 2,000 invoices" is UNVERIFIED.**

The backend is Postgres-only (asyncpg, Postgres-specific Alembic migrations) and the WSL dev host
has neither PostgreSQL nor Docker, so no live scored scenario could be loaded. The two behavioural
scenarios (scored dashboard, unscored empty state) are covered by component and page tests against
`kpis-fixture.ts`; the performance scenario is covered by nothing.

This is the same deferral E4 made, E5 closed with open, and E6 has now inherited. It is E6's M4
line item — *"NFR-02 measured, not assumed"* — and M4 is explicitly mandatory because E4's M4
caught a generation-layer bug no unit test saw. **s6.2 must not be treated as evidence that this
gate is satisfiable later; it is now three epics of accumulated unmeasured assumption.**

## Heutagogical Checkpoint

*(Secondhand — sourced from the implementing session's record. See provenance note.)*

1. **What did I learn?** That `getByText` with an exact string fails when the target shares a
   `<span>` with sibling content — the fix is a regex match on the composed label with the value
   asserted separately, rather than fragmenting component DOM to suit a test. And that a
   `next-intl` `getTranslations` mock must walk dotted keys (`emptyState.title`) by splitting on
   `.`, or every nested lookup silently returns the key string instead of the translation — a
   failure mode that looks like missing translations, not a broken mock.
2. **What would I change about the process?** Verify the full gate scope before committing rather
   than after — the growth edge the session record itself names. Concretely for this story: confirm
   that the verification commands written into the plan can actually run in this repo before the
   plan is approved, instead of discovering at Task 1 that `--scope frontend/` is unresolvable.
3. **Framework improvements?** Three, all real friction rather than preference: (a) `rai gate check
   --scope` resolves relative to `backend/` and cannot target frontend paths in a two-stack repo;
   (b) `rai graph query` and `rai drift check` still fail with `OperationalError: no such column:
   data_json`, so PRIME's retrieval half returned nothing for this story as it has for two epics —
   while `rai pattern add` keeps writing, making the pattern store effectively write-only;
   (c) `.raise/rai/learnings/` does not exist project-wide, so the learning-chain aggregate below
   is structurally N/A rather than merely empty.
4. **What am I more capable of now?** Building a localized Next.js server/client page pair that
   handles the unhappy paths — 409, 404, no active scenario — as first-class rendered states rather
   than error toasts, and typing a frontend against a captured API response so the seam cannot lie.
