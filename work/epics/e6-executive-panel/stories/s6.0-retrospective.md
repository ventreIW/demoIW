# Retrospective: S6.0 — OpenRouter Adapter Hardening

**Dates:** 2026-08-04 → 2026-08-04 · **Estimated:** XS (~1.25h) · **Actual:** ~1.5h (including review)
**Branch:** `main` (commits direct; no story branch created — see "What to improve")

## Summary

Hardened `OpenRouterAdapter` against two known free-tier failure modes that previously degraded to 500 instead of 502:
1. **Missing/empty `choices` in 200 response** → `KeyError`/`IndexError` when accessing `data["choices"][0]["message"]["content"]`
2. **`ReadTimeout` / `TimeoutException`** not caught in retry loop → unhandled exception

Both now raise `ExternalServiceError` → router maps to 502 Bad Gateway (existing pattern in `cases.py:256-257`).

**Delivered:**
- 3 new unit tests (missing choices, empty choices, timeout)
- 2 code changes in `openrouter_adapter.py` (try/except for KeyError/IndexError, except for TimeoutException)
- All 453 backend tests pass
- Integration tests confirm 502 path through router (`test_generate_communication_llm_500_returns_502`)

## What went well

**TDD cycle worked cleanly.** Each task: RED (failing test) → GREEN (minimal fix) → REFACTOR (run all tests) completed in one pass. No back-and-forth.

**Error handling location was correct.** Catching `KeyError`/`IndexError` right at the access point (line 63-66) and `TimeoutException` before retry logic (line 68-70) keeps the retry behavior intact for 5xx while failing fast on timeouts.

**Existing integration test already validated the 502 path.** `test_communications_integration.py::test_generate_communication_llm_500_returns_502` passed without changes — the router → adapter contract was already correct.

**Risk-first ordering paid off.** Task 1 (missing choices) is the higher-probability failure on free tier; fixing it first meant the adapter was partially hardened even if we stopped after Task 1.

## Heutagogical Checkpoint

**1. What did I learn?**
- `httpx.TimeoutException` is the base class for `ReadTimeout`, `ConnectTimeout`, `WriteTimeout`, `PoolTimeout` — catching it once handles all timeout variants. The existing code only handled `HTTPStatusError`.
- respx's `side_effect=httpx.ReadTimeout(...)` raises `SideEffectError` which wraps the original exception — the test fails with the wrapped exception unless the adapter catches it. This is why the RED test failed with `ReadTimeout` bubbling up.
- The router's `ExternalServiceError` → 502 mapping is already solid (established in s5.4). Adapter hardening just needs to raise the right exception type.

**2. What would I change about the process?**
- Enforce `/rai-story-start` as a hard gate before any implementation. The session-start skill's working tree check would have prevented direct-to-main commits.
- For XS stories on isolated adapters, skip the manual integration test task — unit tests + existing integration coverage are sufficient.
- Document the "no branch" decision explicitly in the plan if it happens, so `rai-story-close` expectations are calibrated.

**3. Framework improvements?**
- `rai-story-close` should handle "no branch, commits on main" gracefully (warn + continue) rather than erroring. The skill assumes branch exists.
- Add a `rai story status` or similar that shows "branch: main (no story branch)" so the deviation is visible before close.

**4. What am I more capable of now?**
- Recognizing the timeout exception hierarchy in httpx and placing the catch *before* retry logic to avoid infinite retry on timeout.
- Writing respx tests that simulate transport-level exceptions (not just HTTP status codes).
- Applying the "fail fast on non-retryable errors" pattern consistently.

## Improvements applied

- **None to framework** — the existing patterns (TDD, ExternalServiceError → 502, respx mocking) worked as designed.
- **Pattern worth noting:** "Catch transport exceptions (TimeoutException) before retry logic; only retry on server errors (5xx)." This is a repeatable pattern for any HTTP adapter.
