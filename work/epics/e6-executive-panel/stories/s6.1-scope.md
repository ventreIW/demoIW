# S6.1 Scope — KPI Aggregation (Backend)

**Epic:** E6 · **Size:** S · **Branch:** `story/s6.1/kpi-aggregation-backend`
**ADRs:** [ADR-009](../../../../dev/decisions/adr-009-kpi-reads-persisted-scores.md) (governing),
[ADR-008](../../../../dev/decisions/adr-008-nl-query-constrained-intent.md) (s6.3 consumes this aggregate)

## In Scope

| Item | Surface |
|---|---|
| `PortfolioKpis` + `SegmentBucket` value objects | `app/domain/value_objects/portfolio_kpis.py` (new) |
| `kpi_aggregate_service.fetch_portfolio_kpis()` — composes `IScenarioRepository` (`get_raw_dataset`) and `IScoreRepository` into the aggregate | `app/application/services/kpi_aggregate_service.py` (new) |
| `expected_recoverable()` extracted to a module-level function so the queue and the dashboard share one formula (design D2) | `app/domain/value_objects/prioritized_case.py` |
| `PortfolioNotScoredError` — the 409 refusal lives in the service because s6.3 is the second caller (design D4) | `app/domain/exceptions.py` |
| Six RF-06.1 figures: `total_outstanding`, `total_expected_recoverable`, `collected_to_date`, `recovery_rate_actual`, `recovery_rate_expected`, `cases_by_category` | as above |
| Three segmentation dimensions: `days_overdue_bucket`, `amount_range`, `score_category` | as above |
| `GET /api/v1/scenarios/{id}/kpis` with 200 / 404 / 409 | `app/routers/executive.py` (new) |
| Container provider wiring for the new router | `app/container.py` |
| Unit + router tests, including the partial-payer and unscored cases | `backend/tests/` |
| A real payload captured with `curl` and committed for s6.2 to build its type from | story artifacts |

## Out of Scope

| Item | Reason / destination |
|---|---|
| Any frontend work | s6.2 |
| NL query, `QueryIntent`, prompt templates | s6.3 |
| Changing `/prioritized` to read persisted scores | ADR-009 — E7/E8, deliberately not this week |
| Fixing the dead `?category=High` filter | E5 surface; parked. This story must not *copy* the bug (see AC), but does not fix it |
| Sector as a segmentation dimension | Structurally impossible — `scope.md` §Open questions |
| Caching or a materialized KPI table | YAGNI at demo scale — ADR-009 §Alternatives |
| Trend/time-series metrics | No historical snapshots exist; beyond RF-06.1 |

## Done when

- [ ] `GET /{id}/kpis` returns all six figures plus three segmentation dimensions for a scored scenario
- [ ] An unscored scenario returns **409** naming `POST /{id}/score` — not 200 with zeros
- [ ] An unknown scenario returns **404**
- [ ] `total_outstanding` is produced by `feature_extractor.outstanding_by_client()`, not a second
      definition — asserted by a test that a partial payer contributes net balance exactly once
- [ ] `cases_by_category` has a key for every `ScoreCategory` member, zero-count included, built from
      enum members rather than string literals
- [ ] Per-dimension bucket `client_count`s each sum to the top-level `client_count` — no client
      silently dropped by a bucket boundary
- [ ] `unscored_client_count` is reported, so scoring coverage is visible rather than silently
      omitted from the denominators (design D3)
- [ ] No model is fitted anywhere in the request path (ADR-009) — asserted structurally
- [ ] `pytest` green; OpenAPI schema valid; no new lint or type errors
- [ ] Real payload captured with `curl` against the running app and committed to the story artifacts
- [ ] Retrospective written
