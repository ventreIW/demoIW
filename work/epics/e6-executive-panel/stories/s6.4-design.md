# Feature: NL Query — Frontend

> **Epic**: e6-executive-panel | **Complexity**: simple | **SP**: 3

---

## 1. What & Why

**Problem**: The director can read the E6 dashboard but cannot interrogate it. The backend
`POST /{id}/query` endpoint (s6.3) exists and is merged; nothing on the frontend calls it, so
RF-06.3 / RF-06.4 are invisible to the user.

**Value**: Typing a Spanish question on the executive page returns the same numbers the dashboard
shows, plus a narrative and a citation — the demo's headline loop (M3). An unsupported question
teaches the director what *is* answerable, so the demo stays inside the intent vocabulary.

---

## 2. Approach

**How we'll solve it**: A client `NlQueryPanel` on the `/[locale]/executive` page collects a
question, POSTs it to `/api/v1/scenarios/{id}/query`, and renders one of three outcomes: an
`answerable=true` result (chart + optional narrative + citation), an `answerable=false` refusal
(reasoned message + example questions **from the API's `supported` vocabulary** — never
hardcoded), or an error state (409 → existing unscored CTA, network/5xx → retry). The result chart
is hand-rolled CSS reusing s6.2's chart idiom — no new dependency.

**Components affected**:
- `frontend/src/types/nlQuery.ts` — **create** — request/response types for the query contract
- `frontend/src/lib/api/executive.ts` — **modify** — add `askQuestion(scenarioId, question)` POST client + error mapping (409 → `PortfolioNotScoredError`, 404 → `ScenarioNotFoundError`)
- `frontend/src/components/executive/QueryResultChart.tsx` — **create** — renders `result.series` `{label, value}` as proportional bars, mirroring `SegmentationChart`
- `frontend/src/components/executive/NlQueryPanel.tsx` — **create** — input, submit, loading, calls `askQuestion`, renders answer / refusal / error
- `frontend/src/app/[locale]/executive/page.tsx` — **modify** — render `NlQueryPanel` (scored + active scenarios only)
- `frontend/messages/es.json`, `frontend/messages/en.json` — **modify** — ES/EN key parity

**Lean gates**: KISS — no state store, no multi-turn, no query history. DRY — reuse
`s6.2`'s formatting/error idioms; a **new** `QueryResultChart` is justified because `result.series`
is `{label, value}` and cannot reuse `SegmentationChart`'s `SegmentBucket` props without an
adapter that would be more code than the chart itself. YAGNI — no saved queries, no follow-ups.
MVP — input + one answer render + one refusal render.

**Legacy sweep (mandatory)**: *(a) nothing — net-new.* No V1 query UI exists; no module is
superseded; `SegmentationChart` and the KPI path stay untouched.

**Drift risk**: `governance/drift-hotspots.json` absent — hotspot ranking skipped. **AG2** no
clone: the only shared logic (currency/number formatting) is copied deliberately into
`QueryResultChart`, consistent with how `SegmentationChart` already owns its formatters (application
over extraction at this scale). **AG4** fan-out is 2 new UI files + 1 page + 1 api fn — a single
directed chain, low risk.

**Supply chain gate**: N/A — no new external dependency.

## 3. Interface / Examples

### API / CLI Usage

The frontend calls the already-merged s6.3 endpoint:

```ts
// frontend/src/lib/api/executive.ts (added)
export async function askQuestion(scenarioId: string, question: string): Promise<NlQueryResponse> {
  const res = await fetch(`${API_BASE}/api/v1/scenarios/${scenarioId}/query`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ question }),
    cache: 'no-store',   // only valid option for POST; mirrors fetchKpis
  })
  if (!res.ok) {
    if (res.status === 404) throw new ScenarioNotFoundError(scenarioId)
    if (res.status === 409) throw new PortfolioNotScoredError(scenarioId)
    const body = await res.json().catch(() => ({}))
    throw new Error(body.detail ?? `Failed to answer question: ${res.status}`)
  }
  return res.json()
}
```

### Data Structures

```ts
// frontend/src/types/nlQuery.ts — mirrors s6.3 NlQueryResponse / CannotAnswerResponse
export type RefusalReason = 'out_of_vocabulary' | 'translation_failed' | 'translation_unavailable'

export interface SeriesPoint { label: string; value: number }

export interface QueryResult {
  metric: string
  group_by: string | null
  total: number
  series: SeriesPoint[]
}

export interface SupportedVocabulary {
  metrics: string[]
  dimensions: string[]
  filterable: Record<string, string[]>
}

export interface NlQueryResponse {
  answerable: boolean
  question: string
  scenario: ScenarioRef            // reuse from '@/types/executive'
  scored_at: string
  intent: Record<string, unknown> | null
  result: QueryResult | null
  narrative: string | null         // null on a SUCCESSFUL answer is designed (render chart w/o paragraph)
  reason: RefusalReason | null
  supported: SupportedVocabulary | null
}
```

## 4. Acceptance Criteria

### Must Have

- [ ] AC1 — User submits a Spanish question; `askQuestion` POSTs to `/api/v1/scenarios/{id}/query` with `{question}` and returns the typed response (Vitest-mocked fetch, per s6.2 pattern)
- [ ] AC2 — `answerable=true` renders a `QueryResultChart` from `result.series` (label/value bars) plus the narrative paragraph plus the scenario citation (name + id)
- [ ] AC3 — `answerable=true` with `narrative=null` renders the chart but **no** narrative placeholder/error (designed state)
- [ ] AC4 — `answerable=false` renders an honest "cannot answer" message using the returned `reason`/`message`, and renders example/prompt questions derived **from the API's `supported` vocabulary** — asserting no hardcoded question list exists in the component
- [ ] AC5 — 409 (unscored) surfaces the existing `PortfolioNotScoredError` → actionable "score this scenario" state; no chart or fabricated figure
- [ ] AC6 — network/`translation_unavailable` degradation does not break the KPI dashboard (the panel shows its own error; the dashboard above stays intact)
- [ ] AC7 — ES/EN i18n key parity; `vitest` green; no TypeScript errors

### Should Have

- [ ] Submit disabled while a request is in flight; Enter submits; empty/whitespace question does not submit
- [ ] `reason` surfaces textually (e.g. "translation unavailable") so the operator-facing distinction is legible

### Must NOT

- [ ] MUST NOT hardcode the example-question list or any supported vocabulary — it must come from the API response
- [ ] MUST NOT show a number when a refusal carries none (a refusal never renders `result`/`narrative` figures)
- [ ] MUST NOT modify `SegmentationChart`, `PortfolioKpis`, `SegmentBucket`, or the `/kpis` path (s6.2 locked)
- [ ] MUST NOT add a new charting/styling dependency
