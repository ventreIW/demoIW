## Ordered Task List

### Task 1 — `QueryIntent` domain model + vocabulary
**Size:** M · **Depends on:** none · **AC:** AC8, AC9, AC10

The security boundary. Everything downstream is safe *because* this type cannot hold a bad string.

**Create:**
- `backend/app/domain/value_objects/query_intent.py` — `Metric`, `Dimension`, `Operator`, `Filter`,
  `QueryIntent`, `SUPPORTED_VOCABULARY`
- `backend/tests/unit/test_query_intent.py`

**TDD:**
- **RED** — `Filter(dimension=SCORE_CATEGORY, value="High")` must raise `ValidationError`;
  `"high"` must pass. `Filter(dimension=AMOUNT_RANGE, ...)` must raise, message naming what *is*
  filterable. `QueryIntent(metric="outstanding", sql="DROP TABLE")` must raise on the extra key.
- **GREEN** — `Dimension` members assigned from `portfolio_kpis`'s exported constants (D2, never
  re-typed literals); `Filter` validator resolves its vocabulary from `ScoreCategory` members and
  `_DAYS_OVERDUE_LABELS`; `model_config = ConfigDict(frozen=True, extra="forbid")`.
- **REFACTOR** — `SUPPORTED_VOCABULARY` derived from the enums, never a hand-maintained dict; it
  is what the refusal response renders, so drift would make the help text lie.

**Verification:**
```bash
.venv/bin/rai gate check gate-tests --scope tests/unit/test_query_intent.py
.venv/bin/rai gate check gate-format && .venv/bin/rai gate check gate-types
```

### Task 2 — `query_executor`: intent → numbers
**Size:** M · **Depends on:** T1 · **AC:** AC2, AC3, AC4, AC11

A pure function. No I/O, no async, no repositories — so its tests are exhaustive and instant.

**Create:**
- `backend/app/application/services/query_executor.py` — `execute(intent, kpis) -> QueryResult`
- `backend/tests/unit/test_query_executor.py`

**TDD:**
- **RED** — parametrize over all 3 `Metric` × 4 `group_by` values (12 cells); each must return a
  `QueryResult`, none may raise `NotImplementedError`. Assert grouped `outstanding` by
  `score_category` equals the aggregate's own `segmentation["score_category"]` bucket values
  (AC2). Assert ungrouped `outstanding` equals `kpis.total_outstanding` and is **not** a re-sum of
  buckets (AC4). Assert `client_count` series sums to `kpis.client_count` for every dimension (AC11).
- **GREEN** — `match` on `group_by`, then on `metric`. Ungrouped reads aggregate fields directly.
  Filters applied by selecting matching buckets before projection.
- **REFACTOR** — extract bucket→`SeriesPoint` projection; keep the `match` exhaustive with no
  `case _: pass`.

**Fixture:** build `PortfolioKpis` from `stories/s6.1-payload.json` (curl-captured), not
hand-written literals — s5.1's lesson, s6.2's successful practice.

**Verification:**
```bash

.venv/bin/rai gate check gate-format && .venv/bin/rai gate check gate-types
```

### Task 3 — Translator + translate prompt
**Size:** M · **Depends on:** T1 · **AC:** AC12 (partial)

First task with an LLM in it — and still zero real requests.

**Create:**
- `backend/app/application/services/nl_query_translator.py` — `NlQueryTranslator.translate(question)`
- `prompts/nl_query/v1_translate.txt` — **repo root** `prompts/`, not `backend/prompts/` (G3)
- `backend/tests/unit/test_nl_query_translator.py`

**TDD:**
- **RED** — a stub port returning: clean JSON → `QueryIntent`; JSON in ```` ```json ```` fences →

  user_message=question, model=settings.MODEL_NL_QUERY)` — G4/D5, question below the rules.
- **REFACTOR** — JSON extraction into one helper with the fence-tolerance documented; free-tier
  models wrap JSON in prose routinely.

- `prompts/nl_query/v1_narrate.txt`
- `backend/tests/unit/test_answer_nl_query.py`

**TDD:**

  - `OutOfVocabulary` → `answerable=false`, `reason="out_of_vocabulary"`, vocabulary attached (AC5)

- **GREEN** — fetch aggregate → translate → execute → narrate → cite, in that order.
- **REFACTOR** — one `_refusal(reason)` builder so all three refusal paths cannot drift apart.

### Task 6 — Live verification + ADR-008 amendment
**Size:** S · **Depends on:** T5 · **AC:** the one no stub can reach

**The only task that spends quota.** Budget: **~10 calls of the 50/day**, leaving demo headroom.

**Steps:**
1. Score a scenario, start the app, and run the fixture question set from `s6.3-story.md`
   §Examples against the **real** `MODEL_NL_QUERY` model.
2. Record, per question: the intent returned, whether it matches the expected intent, and the
   narrative. **Including the failures** — a measured bad hit rate is the deliverable, not a
   blocker (ADR-008: wrong ≠ unsafe).
3. Verify one injection question end to end against the live model.
4. **Amend ADR-008**: drop `avg_days_overdue` from the intent sketch, record `limit` as
   deliberately unimplemented, and note the `amount_range` filtering restriction — with the
   evidence from gemba.
5. Write the hit rate into the retrospective.

**Environment caveat, stated up front:** the backend is Postgres-only and this WSL host has neither
Postgres nor Docker (parked 2026-08-07; deferred across E4, E5, E6). **If a live run is impossible
here, T6 does not silently pass** — it is recorded as an explicit open acceptance item in the
retrospective the way s6.2's AC3 was, and the story closes code-complete with that stated. It does
not get quietly marked done.

**Verification:** hit rate recorded in `s6.3-retrospective.md`; ADR-008 amended and committed.

## Execution order

```
T1 ─┬─→ T2 ─┐
    └─→ T3 ─┴─→ T4 ──→ T5 ──→ T6
```

Acyclic — verified: T1 has no dependencies; T2 and T3 both depend only on T1 and not on each other;
T4 depends on T2+T3; T5 on T4; T6 on T5. No back-edges.

**Rationale.** T1 first because it *is* the security property — ADR-008's guarantee is that a
`QueryIntent` cannot hold a hostile string, and until that type exists and is proven, nothing
downstream can claim safety. T2 next because it is pure and exhaustively testable, so the
correctness core is nailed down while there is still no LLM in the system to blame. T3 and T4 add
the model only once the parts it feeds are known-good. T6 last because it is the only task that can
fail for reasons outside the code, and it must not be able to hold up merge-ready work.

T2 ∥ T3 are parallelizable if a second developer picks one up.

## Risks

| Risk | L/I | Mitigation |
|---|---|---|
| Free-tier model returns prose around JSON, or refuses JSON entirely | **H**/M | T3 tests fence-tolerant extraction explicitly; failure degrades to an honest refusal, never a guess. This is the *expected* case, not the exceptional one |
| Translation hit rate is poor on real Spanish | M/M | ADR-008 priced this: wrong ≠ unsafe. Measure it in T6, record honestly, file prompt tuning for E7. s6.4 will surface example questions |
| No Postgres → T6 cannot run live | **H**/M | Stated in T6 as an explicit open acceptance item rather than a silent pass. Third epic carrying this; it is E6's M4 line item |
| Executor grows a `case _: pass` under time pressure | L/H | AC3's parametrization over all 12 cells fails loudly if a branch stops returning numbers |
| Scope creep into s6.4 (rendering, example questions) | M/M | Endpoint returns data only. No template, no HTML, no chart config |
| `gate-lint` stays red from s6.2 and masks a real s6.3 lint error | M/M | Baseline recorded above as exactly 8 errors in named frontend files; any 9th, or any error in `backend/`, is ours |
